## 二、禁区清单（实现前必读）

下列行为视为**超出本迭代范围**，评审与 Code Review 应拒绝：

1. **业务层**：修改 `crew_test`、Agent 编排、导入/同步/生成的**调用次数、参数语义、返回值处理**（除纯展示包装外）。
2. **持久化**：新增业务表字段、变更 JSON schema、变更导出列定义。
3. **假进度**：无阶段回调时实现多段 `progress` 或轮换文案冒充阶段。
4. **新规则**：为「文档上下文」等**新写**一套与现有代码不一致的判定逻辑。
5. **体验指标误实现**：定时器、`time.sleep` 用于「满足 3 秒」、强制 `st.switch_page` 等。
6. **弱化 A/B 级**：为清爽隐藏删除确认、无 Key 报错、同步失败等。

**允许**：`app_ui.py` 内组件重排、`expander` 默认态、`session_state` 中 **`ui_*` / `persist_ui_*` / `dismiss_*` / 展示用聚合** 等**仅影响渲染**的键（见 §五）。

## 五、`session_state` 使用约定（仅展示层）

若 PRD 要求「不再提示」、导入结果摘要聚合、expander 记忆等，建议键名显式前缀，便于检索与 Code Review：

| 用途 | 命名建议 | 禁止 |
|------|----------|------|
| C 级 dismiss | `ui_dismiss_<hint_id>` 或 `dismiss_c_hint_<id>` | 与业务 `current_project` 等混用 |
| 展示用导入摘要 | `ui_memory_import_summary` 等 | 写入导入 API 的返回值到「新业务字段」 |
| Expander 默认态 | 可用 Streamlit `expanded=` + 现有 Key 检测；必要时 `ui_expander_*` | 用 expander 控制按钮 `disabled` 的业务含义 |

**合并导入提示**：在**同一轮渲染**内根据已有变量组合一条 `st.success`/`st.warning` 字符串即可；若需跨轮次聚合，仅缓存**展示字符串**，不缓存应持久化到磁盘的数据结构。

## 六、按 PRD 第十章建议顺序落地

1. **全局**：统一 `ui_texts.yaml` 风格键 + 提示分级（替换零散长句为 caption/折叠）。
2. **高频页**：生成用例 → 项目记忆 → 文档问答/用例对话。
3. **侧栏、设置、历史**：收敛横幅与视觉权重。
4. **扫尾**：emoji 策略、下载按钮文案、折叠标题统一。

实施时以 **需求文档 FR 编号** 勾选项为单位提交，便于回归。

## 七、测试与回归

### 7.1 P0（发版必测）

- 生成用例：上传/粘贴 → 生成 → 导出（列与内容与改版前抽样一致）。
- 项目记忆：导入路径成功/失败判定与改版前一致；仅观察提示条数/位置变化。
- 设置：保存 Key/模型后行为与改版前一致。
- 侧栏：切换模块、云端记忆折叠**不**导致同步按钮逻辑变化（点击仍触发原流程）。

### 7.2 P1（建议）

- 文档问答：无上下文时若已禁用输入，**条件**与改版前逻辑一致（若改版前未禁用，本需求仅允许「映射既有判定」，见 PRD §7.6）。
- 历史记录：删除确认文案变更后，删除结果与改版前一致。

### 7.3 防串味专项检查（对照 PRD §9.4）

- 无假阶段加载。
- 合并提示不改变 API 次数与持久化结果。
- `disabled` 不引入新上下文定义。
