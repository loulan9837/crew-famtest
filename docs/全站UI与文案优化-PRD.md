# 全站UI与文案优化 · PRD

> **文档用途**：在不改变任何业务功能、接口与数据逻辑的前提下，统一全站信息层级、提示体系与文案风格，提升可扫读性与操作确定性。  
> **范围**：仅UI表现与文案；实现载体主要为 `app_ui.py` 布局与 `config/ui_texts.yaml` 配置。  
> **关联文档**：按钮与保存类反馈细则见 [交互反馈优化-PRD.md](./交互反馈优化-PRD.md)；**落地时易与业务混淆的条文、缓解与验收补充**见 [全站UI与文案优化-落地风险分析.md](./全站UI与文案优化-落地风险分析.md)；**整体视觉风格、设计令牌与换肤落地步骤**见 [全站UI视觉风格与换肤方案.md](./全站UI视觉风格与换肤方案.md)。本PRD侧重信息架构与全站文案策略。

---

## 一、背景与问题

当前产品能力已较完整，但体验偏「工程台」，典型问题包括：

1. **提示层级混乱**：大量 `st.info` / `st.warning` / `st.success` 与说明性长句并列，主任务入口被稀释。
2. **文案冗长**：解释型套话多，用户需读很多字才能确定下一步动作。
3. **空态/加载/错误不统一**：同类状态在不同页面表现不一致，缺少统一心智模型。
4. **侧栏负担重**：项目切换、云端记忆、导航、版本信息叠加，扫描成本高。

---

## 二、目标与非目标

### 2.1 目标

- 降低页面噪音，**单页单主任务**视觉焦点清晰。
- 建立**提示分级**（阻断/反馈/说明），解决「提示无关闭、长期占位」的观感问题（高风险信息仍不得简单隐藏，见下文）。
- 文案**短句化、动作化**，术语统一，减少重复解释。
- 在**Streamlit原生**能力内落地，不依赖复杂悬浮、绝对定位或重度前端定制。

### 2.2 非目标

- 不新增或删减功能模块；不改变Agent编排、存储、同步、导出逻辑。
- 不改变「生成用例」仅支持上传与粘贴的产品约束（见项目规范）。
- 不重做多页路由站点形态，仍保留当前工作台+侧栏结构。

### 2.3 交互前提（必须遵守）

若追求「所有提示都可叉掉或自动消失」，**不成立**。删除确认、项目切换丢草稿、凭证缺失、同步失败等**高风险**信息必须可感知且带恢复路径；正确做法是**分级展示**，而非一律弱化或消失。

### 2.4 落地边界（防串味为业务/逻辑变更）

以下约束与 [全站UI与文案优化-落地风险分析.md](./全站UI与文案优化-落地风险分析.md) 一致，实现时**必须**遵守：

- **仅展示层**：凡涉及合并提示、分阶段加载、禁用输入、会话内「不再提示」，仅允许调整**Streamlit展示层**与**session_state中的展示层专用标志**（如折叠默认、dismiss、展示用聚合缓冲）。不得新增或删减接口调用，不得变更存储schema，不得改变Agent编排步骤或与改版前不一致的数据结果。
- **分阶段加载**：分阶段文案**仅绑定已有执行阶段或回调**；若流水线仍为单步阻塞、无阶段信息，则保持**单次**加载提示（`spinner`/`progress`），只优化**单句**措辞。**禁止**为视觉效果伪造不存在的阶段或多段假进度。
- **合并提示**：聚合仅影响**出现次数、位置与展示顺序**，不改变导入/同步API调用次数、返回值含义、持久化结果；若需session_state缓冲，仅存**展示用**键，不写业务字段。
- **禁用输入**（如文档问答无上下文）：门禁条件**只读**既有session_state/已有判定；不新增「何谓有上下文」的业务定义，仅把已有布尔条件映射到组件disabled属性。
- **「不再提示」**：**仅限 C 级**说明性横幅；**A/B 级**（安全、保存结果、致命错误）**不得**用「不再提示」隐藏。
- **折叠与默认展开**：侧栏云端记忆默认折叠、模型配置expander随Key展开等，**仅控制**expanded初始态或容器显隐，**不得**改变记忆同步、导入等按钮的实际可用性或触发逻辑。
- **体验指标**：如「3 秒内可识别主操作」为**体验目标**，**不得**实现为定时器、强制跳转或阻塞逻辑。

## 四、全站信息架构蓝图

```text
App
├─ Sidebar
│  ├─ 项目切换
│  ├─ 当前项目状态（轻量）
│  ├─ 工作台导航（主）
│  ├─ 高级入口（次：设置、编辑Agent）
│  └─ 云端记忆快捷区（建议默认折叠）
├─ MainHeader
│  ├─ 页面标题
│  ├─ 一句话价值说明（可选，单行）
│  └─ 轻量状态条（凭证/环境，按需）
└─ PageBody
   ├─ 主任务区（输入/执行）
   ├─ 结果区（有结果时优先展示）
   └─ 历史/扩展区（降级排版）
```

## 五、提示体系规范

### 5.1 三级分类

| 级别 | 用途 | 表现建议 |
|------|------|----------|
| **A 阻断** | 删除确认、切换项目丢草稿、无Key无法执行、致命解析失败 | 显著色块，紧邻相关操作，含明确恢复动作 |
| **B 反馈** | 保存成功、导入成功、生成完成、同步摘要 | 局部轻量反馈，避免整页顶栏长期占位；同一会话避免重复刷屏 |
| **C 说明** | 格式限制、可选上传、模型建议 | `caption` / `help` / Placeholder / 折叠说明，**不用**横幅替代 |

### 5.2 「可关闭」与常驻

- **C级**说明：优先改为非横幅；若必须用容器，可支持「本次会话不再提示」（**仅C级**；实现走session_state的展示层关闭标志，不写业务数据）。**A/B级不得**套用「不再提示」，避免与关键提示混用同一套关闭逻辑。
- **B级**成功：优先出现在操作区附近；避免与下一屏主内容叠罗汉。
- **A级**与数据安全相关：**不允许**为「清爽」而弱化到不可见。

### 5.3 与既有文档的关系

保存、无变更保存、按钮禁用与 `spinner` 等细则延续 [交互反馈优化-PRD.md](./交互反馈优化-PRD.md)；本PRD补充的是**何时用横幅、何时降级为caption**的全站策略。

## 六、文案总原则

1. **一句一事**：标题说状态，正文说影响，按钮说动作。
2. **先动作后解释**：优先「请上传需求」「请完成设置」，再必要时补一句原因。
3. **去套话**：减少重复的「请先」「本次」「当前」「后点击」链式句。
4. **术语统一**：`API Key`、`Excel`、`Agent`、`PRD` 等全文一致；中文与英文数字边界**不加空格**（产品文案规范）。
5. **失败可复制路径**：错误提示含「可执行的一步」（如打开设置、重试、检查网络），技术堆栈默认折叠或仅日志。

## 七、页面级需求摘要

### 7.1 侧栏

- 导航分组保留，弱化品牌口号占用高度；版本信息沉底、最弱视觉权重。
- 云端记忆快捷区建议默认折叠（`expander` 或等价容器 **`expanded=False`**），展开后保持与主区「粘贴回填」心智一致；**不**改变云端写入、回填、按钮可用性等业务逻辑。

### 7.2 生成用例

- 首屏聚焦：来源切换→主输入→主按钮；模型配置默认折叠，**未配置Key时可自动展开**——该行为**仅**控制expander初始展开态，**不**改变校验顺序、API调用或生成触发条件。
- 顶部配置状态改为**单行状态**或轻量条，避免与历史区抢焦点。
- 无结果时：**空态卡片**（标题+一句引导+主按钮），替代长句 `info` 横幅。
- **加载呈现**：若现有代码**已**暴露多阶段（如多段 `progress` 或回调），可为各阶段配置独立文案，且与代码阶段**一一对应**；若后端仍为单步阻塞、**无阶段信息**，则保持**单次**加载反馈，只优化**一句**加载文案。**禁止**伪造用户可感知的假阶段。

### 7.3 历史记录

- 空态：明确「创建第一份用例」类引导。
- 删除：确认文案短而狠，强调不可恢复与已下载文件不受影响。

### 7.4 需求评审 / 需求风险分析

- 三段式：输入→执行→结果；模块价值一句话说完。
- 风险分析页强调「独立报告」定位，避免与四Agent主流程混淆。

### 7.5 项目记忆

- 分块折叠：搜索与最近、导入需求、全回归用例、设计图、云端同步。
- 临时磁盘部署等**长风险说明**：顶部一条风险摘要+「查看详情」展开，避免整页警告墙。
- 导入结果多状态合并为**一条结果摘要**（减少多处重复success/warning）：聚合**仅**影响展示顺序与条数；导入API调用次数、成功/失败判定、持久化结果与改版前一致；若用session_state，仅存**展示用缓冲**，不写新业务字段。

### 7.6 文档问答 / 用例对话

- 无文档上下文时：输入区置灰或禁用+单行引导，避免误发后长错。禁用条件**必须与**当前「是否已有文档上下文」的**既有**判定一致，**禁止**新写一套业务规则。
- 推荐问题/快捷指令：命名风格统一（短动词+对象）。
- 对话历史默认折叠（如 `expanded=False`），避免首屏被列表占满；**不**改变历史加载 API、条数或存储。

### 7.7 设置

- 单卡片聚合：Key、模型、额度入口；保存反馈局部化。
- 「返回」弱化为次级导航，不抢主表单视觉。

## 八、空态 / 加载 / 错误（全站最低标准）

| 状态 | 必须包含 |
|------|----------|
| 空态 | 标题 + 一句说明 + 一个主行动点 |
| 加载 | 明确进行中 + 防重复提交（与现有交互PRD一致） |
| 错误 | 用户可理解的原因 + 一步恢复动作；技术细节可折叠 |

禁止仅输出「暂无数据」「模块未就绪」而无下一步。

## 九、验收标准

### 9.1 体验

- 核心路径（生成用例、记忆导入、对话）**3秒内**可识别主操作（主观体验目标，**不**用定时器或强制跳转实现）。
- 同一会话内，同类成功提示不重复轰炸；说明性内容明显少于改版前。
- 高风险操作仍有清晰确认与后果说明。

### 9.2 范围

- 功能行为与数据结果与改版前一致（回归对照测试）。
- 文案可配置项优先落在 `config/ui_texts.yaml`；`app_ui.py` 内硬编码中文持续减少。

### 9.3 文案

- 全站术语一致；单句信息量可控；错误与空态均含下一步。

### 9.4 回归与防串味（与风险分析对齐）

| 检查项 | 说明 |
|--------|------|
| 同路径对照 | 改版前后**导出文件、同步结果、生成表结构**一致 |
| 加载呈现 | 无「假阶段」；有多阶段则与代码中的阶段一一对应 |
| 禁用输入 | 禁用条件与「文档上下文」既有定义一致，无新规则 |
| 合并提示 | 仅改变**出现次数与位置**，不改变导入/同步**成功失败判定** |
| 主路径可交互 | 改版后主路径上按钮可点击、输入框可聚焦与输入、文件上传可选；无`pointer-events`、伪元素或装饰层误挡控件等**CSS回归**（与 [全站UI视觉风格与换肤方案.md](./全站UI视觉风格与换肤方案.md) §八一致） |
| session_state安全 | 未对带`key`控件做新增/重排/重命名；若仅有容器级调整，经主路径冒烟与关键页切换验证（与换肤方案§八、§2.1一致） |

## 十、落地建议顺序

1. 统一提示分级与 `ui_texts.yaml` 主文案风格。
2. 优先改「生成用例」「项目记忆」「文档问答」高频页。
3. 收敛侧栏、设置、历史卡片与零散 `st.*` 横幅。
4. 全站扫尾：emoji使用策略、下载按钮文案、折叠区块标题统一。
