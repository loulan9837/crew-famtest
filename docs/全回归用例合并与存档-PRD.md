# 全回归用例合并与存档 · 产品需求文档

> **文档用途**：修复「后导入的全回归 Excel 覆盖前一次导入」的问题，引入“整行精确匹配去重 + 有序合并”的聚合逻辑，并为后续存档与自动更新打基础。
>
> **关联文档**：`项目记忆-RAG与上下文管理-PRD.md`、`项目记忆-重新规划实施方案.md`

---

## 一、背景与问题

### 1.1 现状

- 在「项目记忆」Tab 中导入全回归用例时，使用固定的 `source_id="full_regression"`。
- 导入顺序示例：
  - 第一次：导入 `A 模块全回归.xlsx`，解析结果写入 `full_regression`；
  - 第二次：导入 `B 模块全回归.xlsx`，解析结果直接覆盖 `full_regression` 的内容。
- 后果：
  - 项目记忆中的“全回归用例”只保留**最后一次导入**的 Excel 内容；
  - 文档问答 / 生成用例时，Agent 看不到 A+B 的全集，只看到 B。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 行级并集 | 多次导入全回归 Excel 时，项目记忆中的「全回归用例」始终是所有导入文件的**行级并集**（A∪B∪C…），按「整行精确匹配去重 + 有序合并」规则计算 |
| 存档保留 | 每次导入保留一条**原始存档记录**，便于后续回溯与检查 |
| 聚合视图稳定 | 对外暴露给 Agent 与导出的仍是一条固定的“聚合视图记录”，不影响现有调用方 |
| 导出支持 | 在项目记忆中，支持一键导出当前「聚合后的全回归用例」为 Excel |

## 二、核心概念

### 2.1 存档记录（Archive Entry）

- 含义：每次导入一份 Excel / 文本时，对应的一份“原始全回归用例内容”。
- 标识：
  - `source_type = "test_cases"`（沿用现有）
  - `source_id = "full_regression:{import_id}"`（import_id 可为 `时间戳 + hash`）

### 2.2 聚合视图记录（Aggregated Entry）

- 含义：所有存档记录按“整行精确匹配去重 + 有序合并”后的结果，是 Agent 与导出的唯一数据源。
- 标识：
  - `source_type = "test_cases"`
  - `source_id = "full_regression"`（沿用现有约定）

### 2.3 行级精确去重（Line-level Exact Dedup）

- 判重标准：两行文本**完全相同**（字符串相等）时，视为重复行。
- 规则：
  - 旧内容的所有行先按现有顺序保留；
  - 新内容的行，若整行文本在旧内容中已存在，则不再追加；否则按顺序追加；
  - 不做模糊/近似去重，避免误删（例如标点或空格略有差异的行被视为不同用例，都会保留）。

## 三、业务流程与交互

### 3.1 单次导入全回归用例

1. 用户在「项目记忆」Tab 中，上传/粘贴一份全回归用例（Excel / 文本）。
2. 系统解析为按行描述的用例文本 `content_new`（沿用现有解析规则）。
3. 系统写入一条**存档记录**：
   - `source_type = "test_cases"`
   - `source_id = "full_regression:{import_id}"`
   - `title = "全回归测试用例 - {文件名或用户备注}"`
   - `content = content_new`
4. 系统读取当前“聚合视图记录”的内容 `existing_content`（若不存在则视为空）。
5. 系统执行“行级精确去重 + 有序合并”，生成 `merged_content`。
6. 系统将 `merged_content` 写回 / 新建“聚合视图记录”，标记为「全回归测试用例（聚合）」。
7. UI 提示：
   - 若本次导入带来了新增行：展示“已合并 {新增行数} 条全回归用例”；
   - 若没有任何新增行：提示“导入内容与现有聚合结果一致，已跳过”。

### 3.2 聚合视图在系统中的使用

- **文档问答 / 生成用例**：
  - 所有需要“全回归用例”的 Agent 上下文，仅从 `source_id="full_regression"` 的聚合视图读取；
  - 不直接遍历所有存档记录，避免重复。
- **项目记忆页展示**：
  - 聚合视图仍可作为「全回归用例」区块中的当前状态摘要（例如显示合并后的行数）。

### 3.3 导出逻辑

- 在项目记忆 Tab 的“全回归用例”区块新增按钮：
  - 【导出全回归用例（聚合）】：
    - 将聚合视图内容转换为表格结构后导出 Excel；
    - 文件名建议为：`全回归用例_聚合_{日期时间}.xlsx`。
- 后续迭代（非本期目标）：
  - 在“导入历史”中为每条存档记录提供【导出此批用例】按钮；
  - 支持单次导入的用例单独导出（版本比对/回顾用途）。

## 四、自动更新与扩展点

### 4.1 自动更新

- 每次导入全回归用例时：
  - 自动写入新的存档记录；
  - 自动重算聚合视图并写回；
  - 可选：为 Gemini Context Cache / Agent 知识库打上“脏标记”，下次使用前触发重建。

### 4.2 后续扩展（非本期）

- 存档视图：
  - UI 中展示所有 `source_id` 以 `full_regression:` 开头的记录列表；
  - 每条包含：导入时间、文件名/说明、行数概览、hash 等信息。
- 版本对比 / 回滚：
  - 支持选择一个/若干历史存档版本，重新生成新的聚合视图；
  - 支持“仅基于某几个版本”重算聚合结果（例如只用最近两次全回归）。

## 五、验收标准

| 编号 | 验收项 |
|------|--------|
| AC1 | 依次导入 `A 模块全回归.xlsx` 与 `B 模块全回归.xlsx` 后，聚合视图中的全回归用例文本包含 A 与 B 的所有行，重复行只出现一次（以整行完全相等为判重标准）。 |
| AC2 | 在已有 A、B 聚合结果的基础上再导入 C，聚合视图为 A∪B∪C 的行级并集；存档列表中可以单独看到 A、B、C 三次导入记录。 |
| AC3 | 导入一份与当前聚合视图内容完全相同的 Excel 时，聚合视图内容不变，UI 提示“导入内容与现有聚合结果一致，已跳过”或等价文案。 |
| AC4 | 点击【导出全回归用例（聚合）】后，导出的 Excel 中行数与聚合视图内的行数一致，表头结构与现有全回归导出格式一致。 |
| AC5 | 文档问答与生成用例时，Agent 看到的“全回归用例”来自聚合视图（A∪B∪C…），而非最后一次单独导入的那一份。 |
