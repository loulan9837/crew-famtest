# 设计图导入结果与历史视图 · 产品需求文档

> **文档用途**：在现有「设计图导入」能力基础上，补齐导入结果反馈与历史设计图列表，让测试/产品清楚知道：本次上传的每一张图是否导入成功、系统已经存了哪些版本/需求/位置的设计图。
>
> **关联文档**：`设计图导入-PRD.md`、`项目记忆-RAG与上下文管理-PRD.md`

---

## 一、背景与问题

### 1.1 当前行为

- 在「项目记忆」Tab 中导入设计图时：
  - 用户上传一批图片（或 PDF）；
  - 系统通过 Gemini Vision 解析为结构化文本，调用 `add_entry_with_dedup("design_mockup", ...)` 写入项目记忆；
  - 导入成功时给出一个整体的成功提示（如“设计图已解析导入，下次生成用例时 Agent 将参考。”）。
- 存储层已经有 `source_type = "design_mockup"` 的记录，但**UI 层没有设计图维度的历史视图**。

### 1.2 现存痛点

1. **导入结果不可见**：
   - 多张设计图同时上传时，用户无法区分：
     - 哪几张成功导入；
     - 哪几张因 hash 去重被“已跳过”；
     - 哪几张解析失败（Vision 错误 / PDF 解析失败）。
2. **已导入设计图清单不可见**：
   - 设计图文件名已经约定了语义（例如 `v6.5_paid_media_解锁列表`），但用户在项目记忆中看不到**一张“当前系统里有哪些设计图”的列表**。
   - 无法回答：
     - 当前项目记忆里是否已有某个版本（v6.5 / v6.6）的对应位置设计图；
     - 某个需求相关的完整设计图集是否已经补齐。

## 二、目标与范围

### 2.1 目标

| 目标 | 说明 |
|------|------|
| 明确导入结果 | 本次上传的每一张设计图，要有明确的逐条结果：成功 / 已存在（跳过） / 失败（含错误原因） |
| 可见的历史清单 | 在「项目记忆」Tab 中提供一个“设计图历史”视图，按时间展示当前项目的所有设计图记录 |
| 依赖文件名的语义 | 历史列表中显式展示文件名（如 `v6.5_paid_media_解锁列表`），作为版本、需求、位置的主要识别依据 |
| 与现有逻辑兼容 | 不改变现有设计图解析和写入 memory_store 的方式，仅在 UI 和查询层做增强 |

### 2.2 范围

- 本期只针对：
  - 「项目记忆」Tab 中的设计图导入模块；
  - 设计图导入结果反馈；
  - 设计图历史视图展示；
  - 单个设计图文本内容的预览。
- 不在本期实现：
  - 设计图与用例之间的显式关联（如“这张图对应哪些用例 ID”）；
  - 版本对比/回滚；
  - 图片缩略图预览（仍以文本描述为主）。

## 三、用户场景与交互

### 3.1 导入结果反馈（本次上传）

1. 用户在「项目记忆」Tab 的“导入设计图”区块上传 1～N 张图片 / PDF。
2. 点击【解析并导入】后，系统逐张处理：
   - 对每一张图展示一条状态行，例如：
     - 成功：`✅ v6.5_paid_media_解锁列表.png — 已解析并写入项目记忆`
     - 已存在（hash 命中）：`ℹ️ v6.5_paid_media_解锁列表.png — 内容未变更，已跳过（已于 2026-03-05 14:32 导入）`
     - 失败：`❌ v6.5_paid_media_解锁列表.png — 解析失败：Gemini Vision 超时`
3. 若本批至少有一张成功导入，保留原有的整体成功提示（如“设计图已解析导入，下次生成用例时 Agent 将参考。”），但补充总数统计（成功/跳过/失败数量）。

> 行为约束：导入结果反馈**只影响当前交互，不改变存储结构**。

### 3.2 历史设计图列表（按项目）

在「项目记忆」Tab 新增一个“设计图历史”子区块，位置建议在“导入历史时间轴”附近，或作为其中一部分按类型区分。

**展示要求：**

- 列表按时间倒序（最近导入在上），每条记录展示：
  - 时间：`created_at`；
  - 文件名：来自最初解析时的原始文件名，例如 `v6.5_paid_media_解锁列表`；
  - 标题：`title`（如 `设计图：v6.5_paid_media_解锁列表`）；
  - 来源：上传（图片 / PDF）、页数信息（若有）；
  - 摘要：Librarian Agent 生成的 150 字摘要（若存在）。
- 展示形式：
  - 建议使用 `st.expander` 列表：
    - 折叠标题行：`[时间] 文件名 — [有摘要✓ / 待生成 / 失败✗]`
    - 展开内容：
      - 设计图文本描述（full_description 前 2000 字）；
      - Librarian 摘要全文；
      - 基本元信息（文件名、导入方式、页数）。

**交互能力（本期）**：

- 滚动查看最近 N 条设计图记录；
- 点击某条记录展开详情；
- 若摘要生成失败，可在该条记录下提供【重试摘要】按钮。

**交互能力（后续可扩展，非本期）**：

- 根据关键字过滤（文件名/标题）；
- 按版本前缀筛选（例如 `v6.5_` / `v6.6_`）。

## 四、数据与状态约定

### 4.1 存储约定（沿用现有设计图导入方案）

- 设计图记录统一使用：
  - `source_type = "design_mockup"`
  - `source_id`：当前实现中为图片哈希前缀或类似唯一标识；
  - `title`：建议为 `设计图：{原始文件名}`；
  - `content`：设计图的结构化描述文本（含多页合并时的章节标题）；
  - `summary` / `agent_summary` / `agent_summary_status`：由 Librarian Agent 生成或留空。

### 4.2 会话状态（st.session_state）

- 不新增全局状态，仅在导入交互中增加一个本次结果列表，例如：
  - `design_import_results`：数组，每项包含：
    - `name`：原始文件名；
    - `status`：`"success" | "skipped" | "failed"`；
    - `message`：说明（如“已导入”“内容未变更，已跳过”“解析失败：xxx”）；
    - （可选）`imported_at`：查到的最近一次导入时间（用于 skipped 场景）。
- 切换 Tab 或页面刷新后，该结果列表可置空，不做长期持久化。

## 五、非功能约束

- **性能**：设计图历史列表默认展示最近 N 条（如 20 条），防止一次性加载过多大文本导致页面卡顿。
- **项目隔离**：在双项目模式下，设计图历史必须按 `project_id` 过滤：
  - Fambase / RM11 各自只看到自己的设计图历史；
  - 不跨项目展示。
- **向下兼容**：已有的设计图记录（在本功能上线前导入的）无需迁移：
  - 列表中仍可正常展示（基于已有的 title + content）；
  - 仅缺少文件名字段时，使用 title 作为主要显示文本即可。

## 六、性能优化与模型选择（Zip 场景）

### 6.1 性能痛点（Zip 内多张 PNG）

- 当前：上传一个包含大量 PNG 的 zip 包时，系统会逐张图片调用 Gemini Vision 解析，整体耗时较长。
- 痛点：
  - 用户无法感知进度，误以为系统“卡死”；
  - 大量图片一股脑跑 Vision，整体耗时和 Token 消耗不可控。

### 6.2 约束与目标

| 项 | 约束 / 目标 |
|----|-------------|
| 全量解析 | 对 zip 中的设计图**全部逐个解析**，不设置图片数量上限；解析过程中提供进度反馈，避免用户误以为系统卡死 |
| 总体大小限制 | 延续现有单文件 / 总大小限制（10MB / 50MB），Zip 在解包前先做体积检查，过大时在上传阶段直接给出提示 |
| 进度反馈 | 解析 zip 中多张图时，提供简单的进度反馈（当前张数 / 总张数），避免“静默长时间等待” |
| 模型强制使用免费档 | 设计图解析（含 Zip 内图片）**只能使用免费的 Gemini 模型**，无论全局配置了什么模型；禁止走高成本模型 |

### 6.3 模型选择规则（设计图专用）

- 对于设计图解析调用 `_parse_design_image_with_gemini`：
  - 优先读取专用环境变量（如 `GEMINI_FREE_VISION_MODEL`），若为空，则回退到一个默认的免费模型（例如 `gemini-2.5-flash-lite` 或等价免费档）；
  - 忽略全局默认模型设置（`defaults["gemini_model"]`），避免被误配置成高成本模型；
  - UI 中的模型下拉选择**不影响**设计图解析，减少误用风险。

> 目的：在不限制主流程用例生成模型选择的前提下，对设计图解析路径单独施加成本上限。

## 六、验收标准

| 编号 | 验收项 |
|------|--------|
| AC1 | 用户上传多张设计图后，每一张均有单独的导入结果行（成功 / 跳过 / 失败），失败时包含错误原因描述。 |
| AC2 | 若某张设计图内容与历史记录完全相同（hash 命中），导入结果显示“内容未变更，已跳过”，并在文案中说明最近一次成功导入时间。 |
| AC3 | 在「项目记忆」Tab 中，能看到一个按时间倒序展示的“设计图历史”列表，至少展示时间、文件名、标题、摘要状态。 |
| AC4 | 点击历史列表中的任意一条记录，可以展开查看该设计图的结构化描述文本与 Librarian 摘要。 |
| AC5 | 双项目场景下，切换 Fambase / RM11 后，设计图历史列表的内容随项目切换，互不串数据。 |
| AC6 | 现有设计图导入能力（解析+入库）与生成用例逻辑不受此次改造影响。 |
| AC7 | 上传包含多张 PNG 的 zip 时，所有图片都会被逐个解析，UI 有明显进度提示（当前张数/总张数），整体体验较当前版本有明显改善。 |
| AC8 | 无论全局设置的默认 Gemini 模型为何，设计图解析实际调用的始终是配置的免费模型（可通过日志或测试配置验证）。 |
