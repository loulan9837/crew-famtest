# 页面切换保留用户输入 · 开发实施文档

> **文档用途**：供研发实现「侧栏切换模块后保留用户输入」的**技术方案、边界与验收要点**。  
> **受众**：开发、测试。  
> **创建日期**：2026-03-30

---

## 一、背景与根因

在部分 Streamlit 版本与特定组合下，如果仅依赖 widget 默认管理的 `session_state`，在模块切换或刷新时存在 **输入状态丢失的风险**（不同版本行为并非完全一致，调试成本较高）。

因此需要 **与 widget 解耦的持久化备份**（例如 `persist_ui_<widget_key>`），在重新进入页面时写回 widget 使用的 `session_state` 键，用统一的工程约定消除版本差异带来的不确定性。

---

## 二、推荐实现模式（抽象）

1. **镜像键**：对每个需要保留的控件，维护 `persist_ui_<widget_key>`，仅用于跨页面保留，不随 widget 卸载而失效。
2. **恢复**：在创建 widget **之前**，若 `persist_ui_*` 存在，则将其写入 `session_state[widget_key]`（与 Streamlit 约定一致：先设 state 再创建 widget）。
3. **同步**：通过 `on_change` 回调，或在模块末尾批量 `_persist_widget_state(widget_key)`，将当前值写入 `persist_ui_*`。
4. **已有二进制缓存**：如上传文件的 `*_cache` 字节缓存，继续与 `persist_ui_*` 配合使用，避免重复上传。

具体命名与辅助函数位置由 `app_ui.py` 统一维护，避免散落魔法字符串。

## 三、实施清单（按模块）

| 模块 | 建议纳入 persist 的控件类型 | 备注 |
|------|------------------------------|------|
| 生成用例 | 来源 radio、粘贴、上传、模型选择等 | 与现有 upload cache 一致 |
| 设置 | **非敏感字段**（如模型选择、开关类配置）、其他文本类 | Key 等敏感字段不在本期范围内，如需草稿能力需单独 PRD 与安全评审 |
| 项目记忆 | 搜索、需求粘贴、标题、上传、用例粘贴、摘要 `text_area` | 摘要需与 `load_project_memory` 的默认回填顺序协调，避免覆盖未保存编辑 |
| 用例补充 | 指令类 `text_area` | 与按钮提交逻辑解耦 |
| 历史记录 | 筛选 | 若有 |
| 风险报告 / 文档问答 | 来源、粘贴 | 同上 |
| 编辑 Agent | 路径等轻量控件；**复杂配置草稿不在本期范围** | 适合在渲染前批量 restore、模块末尾批量 persist；Agent 配置草稿需单独 PRD |
| 用例对话 | 历史搜索、来源 radio、粘贴需求/用例 | **历史 selectbox** 若选项为运行时对象，建议用 **run id** 或索引持久化，见下节 |

## 四、特殊边界

### 4.1 `st.file_uploader`

- 使用 `on_change` 同步 `persist_ui_*`；若封装在 `app_ui_components.render_file_uploader`，需支持透传 `on_change`。
- 大文件仍以字节缓存与 `persist` 协同，避免仅依赖 `UploadedFile` 的会话状态。

### 4.2 `st.selectbox` 与动态选项（用例对话「历史生成记录」）

- 若 `options` 为每次请求新建的 `dict` 等对象，**不可**直接假定 `session_state` 中的对象与新一轮 `options` 相等。
- 推荐：持久化 **稳定主键**（如 `run_id` / `record_id`），渲染时根据 `options` 反查选中项；或持久化 **index**（需与列表长度一致时校验）。

### 4.3 `st.chat_input`

- 确认目标 Streamlit 版本是否支持 `key`；若不支持或行为不一致，跨页保留草稿可列为非 P0 或单独说明。
- 根据《页面切换保留用户输入 · PRD》，当前版本**不要求**对 `st.chat_input` 实现跨页面草稿，测试不以此作为 P0 验收项。

### 4.4 用户主动清空

- 「结束对话」「清空」等操作应同时清除对应 `persist_ui_*`，避免下次进入仍看到旧内容。

### 4.5 多项目工作台（`current_project`）

- 建议以 `current_project` 为作用域，将需求输入型模块的 `persist_ui_*` 按项目分命名空间（如 `persist_ui_FAMBASE_*` / `persist_ui_RM11_*`）：  
  - 切换项目时，仅切换当前使用的命名空间，不清空其他项目已有草稿，也不会在新项目中复用旧项目的输入。  
  - 设置等全局通用模块的非敏感字段可不做项目维度隔离，按全局草稿处理。

## 五、非功能要求

- **MVC**：恢复/持久化逻辑可放在 `app_ui` 的薄层，**不**与 Crew/Gemini 等业务逻辑耦合在同一函数内（遵守项目规范）。
- **文案**：用户可见文案走 `config/ui_texts.yaml`。
- **安全**：不将 Key 写入新日志文件；目录与路径校验遵循既有 `.cursor/rules`。
- **Excel 注入**：若 persist 内容与导出 Excel 相关，清洗逻辑不变。

---

## 六、测试建议

**P0 必测（发版关卡）**

1. 对 P0 模块（生成用例、设置页非敏感字段）至少一条：**填写 → 切换 2 个其他模块 → 切回 → 内容仍在**。
2. 设置：**改非敏感字段（如模型）未保存 → 切换 → 切回 → 仍为修改后的值**；Key 不做此类验证。
3. 上传：对于生成用例等模块，切换后 **仍可生成/导入**（依赖缓存 + persist）。
4. 结束对话 / 清空后：**不应**恢复旧粘贴。

**P1 建议测试（非阻断）**

5. 对项目记忆、需求风险分析、文档问答、用例补充、用例对话等 P1 模块，可参考 1、3 的路径做抽查验证，不作为本期发版关卡。
