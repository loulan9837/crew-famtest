## 一、范围与前提（〇章对齐）

- [ ] 已确认：**仅云端 R2 + 远程 Postgres** 适用本方案；本地 Sqlite/JSON **不适用**、另有说明。
- [ ] 已确认：本期为 **整库 + manifest 绑定的 R2 数据集**；**不按 project_id** 单独恢复。
- [ ] 已确认：暂不多用户；总数据量预期 ≤1GB。

---

## 二、单次 backup run（第二章对齐）

- [ ] **成功定义**：仅当 PG 上传并校验 + R2 步骤完成并校验 + **总 manifest** 写入并校验 → 才为 `completed`。
- [ ] **失败/部分**：任一步失败 → **不淘汰**旧世代、**不**标「最新可用」。
- [ ] **状态机**（若实现）：可从 `started` 追踪到 `failed` 的步骤，且日志 **无密钥泄露**。
- [ ] **manifest**：每个 `backup_run_id` **有且仅有一份** JSON；含 `schema_version`、`postgres`（key+sha256+size）、`r2_dataset`、各步 UTC 时间。
- [ ] **恢复第一步**：Runbook 要求 **先校验 manifest**，再取 dump / R2。

---

## 三、一致性与裂脑（第三章对齐）

- [ ] 已理解：**软一致窗口**（分钟级）为预期，恢复后需 **调和**。
- [ ] 已区分场景：**整站回滚** vs **仅修裂脑（生产库未回滚）**；调和「以谁为准」不同。
- [ ] 默认：**quarantine + 人工确认**，非自动删生产对象。
- [ ] 悬空记录：业务路径 **不得** 对 R2 404 静默成功。

---

## 四、调度与连接（第四章对齐）

- [ ] **禁止** Streamlit 应用内定时任务作为备份源。
- [ ] **`pg_dump` 连接串**：使用 **备份专用直连/非池化**（与 App Pooler **分离**）。
- [ ] GitHub Actions：仅在 **受保护/default 分支** 跑带 Secret 的 workflow；权限 **最小化**。
- [ ] R2 凭证：**仅** `backups/` 前缀（或独立备份桶）的 Put/List/Get/Head；定期 **轮换**。
- [ ] 日志：**无** echo 连接串/Secret；失败信息 **脱敏**。
- [ ] 已评估：job **超时/OOM**；超阈值是否有 **VPS/自建 Runner** 预案。

---

## 五、保留与防灾（第五、七章对齐）

- [ ] **多世代**（如 ≥7 日备）+ 最长保留期（如 30 天）已配置。
- [ ] **仅** `completed` run 后才执行淘汰。
- [ ] **写后删**：新备份校验通过前 **不删**旧备份。
- [ ] **体积熔断**：默认阈值已配置；**override** 有 **审计**（人、时、因、`backup_run_id`）。

---

## 六、PITR 与 RPO/RTO（第六、九章对齐）

- [ ] 对外表述：**L1 全量快照**（按 `backup_run_id`），**非**任意时刻 PITR，除非另购 L2。
- [ ] **RPO**：备份周期 + 软一致窗口已写入对外说明。
- [ ] **RTO**：有目标数字；**每季度** staging 全链路恢复演练已排期。

---

## 七、恢复与切流（第九章对齐）

- [ ] 恢复顺序：**manifest → 空库/branch → 只读校验 → 调和 → 切流**；禁止半恢复对生产读写。
- [ ] quarantine **回滚步骤**已文档化。

## 八、安全与合规（第八章对齐）

- [ ] 备份桶/对象：**私有**；**SSE**（或平台等价）；**无** public-read。
- [ ] 下载恢复：**短期**预签名或 IAM。
- [ ] 备份与 **用户删数/被遗忘权**：已按主文档「默认桶级保留」口径对齐；若需单条抹除已立项。
