# 需求风险评估报告 · 项目流程总览 PRD

> **审查对象**：`docs/项目流程总览.md` 及关联文档（Agent知识库-PRD、项目记忆摘要修复、项目记忆-重新规划实施方案、设计图导入-PRD 等）
> **审查角色**：逻辑闭环与边界防御，非测试用例输出

---

## 需求风险评估报告

| 风险模块 | 风险类型 | 风险详情描述 | 严重等级 | 建议补充方案 |
|----------|----------|--------------|----------|--------------|
| 生成用例流水线 | 逻辑缺失 | 状态仅隐含「触发→四Agent接力→完成」；未定义用户中途刷新/关Tab、单Agent超时或失败后整体状态（中止/跳过该Agent继续/重试）、是否持久化「部分完成」中间结果 | 高 | 显式定义流水线状态机：running/success/partial_fail/fail；约定单Agent超时或API失败时整链中止并回写状态；约定刷新/关Tab视为用户取消，不持久化未完成结果或标记为 cancelled |
| 生成用例流水线 | 逻辑缺失 | 未定义「取消」与「超时」：用户点击生成后无法中止；单次请求或整链无超时阈值与超时后状态（failed/retry） | 高 | 补充取消入口（如生成中展示「取消」按钮并中断后续Agent调用）；为每步Agent与整链配置超时时间，超时统一置为 failed 并允许重试 |
| 生成用例流水线 | 边界异常 | 弱网/断线导致四Agent中某一环超时或连接中断时，PRD未定义部分成功（如1、2号完成，3号超时）的持久化、恢复或重试策略，易出现「跑了一半不知道从哪续」 | 高 | 约定部分成功不写Excel仅写日志/中间态；提供「从第N号Agent重试」或「仅重跑失败环节」的规则与入口 |
| 项目记忆·导入历史摘要 | 逻辑缺失 | agent_summary_status 为 pending/success/failed，无「超时自动置为 failed」；若后台生成摘要的调用挂死或长时间无响应，条目永久停在 pending，仅依赖用户手动重试 | 中 | 为摘要生成设定超时（如60s），超时自动 update_agent_summary(..., "failed")；或显式约定「无超时，仅依赖手动/批量重试」并写入PRD |
| 项目记忆·导入历史摘要 | 边界异常 | 批量生成缺失摘要与单条导入触发摘要并发时（如批量执行中用户再导入新文档），未定义Gemini限流、DB写冲突或请求排队策略 | 中 | 约定摘要生成串行化（全局锁或队列），或显式允许并发并规定限流与失败重试策略 |
| Agent知识库 | 逻辑缺失 | 知识库状态为「未生成/已生成/过期(≥7天)」+ 手动刷新；未定义「刷新中」时用户切Tab或关页、刷新请求超时、刷新失败后「最后更新时间」是否回滚 | 中 | 显式增加「刷新中」状态；约定刷新超时时间与超时后置为失败、保留旧知识库与旧时间戳；约定用户离开不取消已发起的LLM请求，仅前端停止轮询 |
| Agent知识库 | 边界异常 | 双Tab同时点击「刷新知识库」或「进入项目记忆页触发自动更新」时的并发行为未定义，可能导致双份LLM调用、写文件冲突或「最后更新时间」竞态 | 中 | 约定单实例内刷新串行（如全局锁/disabled按钮直至完成），或文档明确「不支持多Tab同时刷新」 |
| 项目记忆·存储后端 | 历史冲突 | 流程总览称「无项目记忆存储时退化为 project_memory + 模块定义，生成用例仍可用」；Agent知识库PRD称「4个Agent默认使用知识库(agent_knowledge.md)」。若 memory_store 不可用，agent_knowledge 由何而来、是否仍会尝试构建，与「退化后仍可用」的拼装顺序是否一致未在总览中闭合 | 高 | 在总览或Agent知识库PRD中明确：memory_store 不可用时是否仍构建/读取 agent_knowledge；get_project_context_for_agent 在 MEMORY_AVAILABLE=False 时的精确拼装顺序（是否含 agent_knowledge.md）及降级优先级 |
| 项目记忆·存储后端 | 逻辑缺失 | Sqlite 不可用→Json 降级有定义；「Json积累数据后环境恢复Sqlite」仅预留 migrate 工具，未定义同一会话内若运行时恢复 sqlite3（如动态加载）是否自动切回、是否双写、迁移前Json是否只读 | 低 | 明确运行时不自动从Json切回Sqlite；迁移仅通过显式调用迁移工具；迁移期间或迁移前Json后端只读或双写策略二选一并文档化 |
| 需求/文档输入 | 边界异常 | 需求文档粘贴或上传无长度上限；超长文本（如500k字符）对四Agent与 project_context 拼装、Token截断策略未定义，易导致超限或截断后语义不完整 | 高 | 规定需求文档最大字符数或最大Token预估；超出时拒绝或分片策略；截断时在UI/日志中明确提示「已截断」及截断规则 |
| 需求/文档输入 | 边界异常 | 零数据场景未统一定义：无 project_memory.md、无 memory_entries、全回归Excel为0行、上传0字节文件、设计图仅支持PNG/JPG时用户上传webp/svg等，各模块的提示与降级不一致 | 中 | 在总览或各模块PRD中集中定义：空 project_memory、空 memory_entries、0行Excel、0字节文件、非支持图片格式的校验与提示文案及是否允许继续生成 |
| 设计图导入 | 历史冲突 | 设计图导入PRD引入 source_type=design_mockup；需确认 memory_entries 表结构与 list_import_history/get_recent_for_agent 等老逻辑是否已全部支持该枚举，否则历史数据或筛选会漏掉/错乱 | 中 | 在实施文档或数据契约中明确 design_mockup 与现有 source_type 枚举、历史条目的兼容性；若有旧版本无该字段，需约定默认值或迁移 |
| 版本号展示 | 边界异常 | 侧栏版本号来自 config/version.yaml；未定义文件缺失、格式错误、无 version 键时的展示内容与降级（空、占位符或隐藏），可能造成前端报错或空白 | 低 | 约定 version.yaml 缺失或异常时展示「版本未知」或隐藏版本区块，并记录日志 |
| 生成用例·历史记录 | 逻辑缺失 | 「删除不再需要的历史记录」未定义删除是否级联（如仅删展示条目还是同步删本地JSON/DB中的输出路径）、多Tab下删除后他Tab是否即时失效；若输出文件已被用户移走，删除记录后是否允许「仅删记录不删文件」 | 低 | 明确删除为软删还是硬删、是否动文件系统；多端一致性采用 session_state 或统一存储的刷新策略 |
| 文档问答/风险分析 | 边界异常 | 文档来源为「项目记忆中选择近期文档」时，若项目记忆不可用（MEMORY_AVAILABLE=False）或近期列表为空，PRD未定义入口是否隐藏、禁用或提示「暂无可用文档」 | 中 | 规定 MEMORY_AVAILABLE=False 或列表为空时，文档来源下拉/选择器的展示与禁用逻辑及提示文案 |

**说明**：本表仅做需求与逻辑层面风险识别，不输出测试步骤；具体实现与验收需由开发与测试按上述建议在PRD/实施文档中闭环后再执行。
