# 设计图导入结果与历史视图 · 开发实施文档

> **依赖**：`docs/设计图导入-PRD.md`、`docs/设计图导入历史-PRD.md`、`memory_store.py` 现有 `design_mockup` 实现。
>
> **目标**：在不改变现有设计图入库逻辑的前提下，增加导入结果反馈和历史设计图列表。

---

## 一、涉及模块与现状

| 文件 | 作用 |
|------|------|
| `app_ui.py` | 「项目记忆」Tab 渲染：设计图导入区块、历史列表 UI |
| `memory_store.py` | 存储设计图记录：`source_type = DESIGN_MOCKUP_SOURCE_TYPE` (`\"design_mockup\"`) |
| `config/ui_texts.yaml` | 设计图导入与历史视图相关文案 |

现有行为（简要）：

- 导入设计图时：
  - 读取上传文件字节；
  - 通过 Gemini Vision 解析为结构化描述文本 `full_description`；
  - 调用 `add_entry_with_dedup(DESIGN_MOCKUP_SOURCE_TYPE, full_description, source_id=file_hash[:16], title=f"设计图：{file_name}", ...)`；
  - 非 `skipped` 时，调用 `_generate_entry_summary` 生成 Librarian 摘要。
- 项目记忆 Tab 中已有“导入历史时间轴”，但其粒度是 `memory_entries` 全量视角，不区分专门的“设计图列表”。

## 三、导入结果反馈实现（app_ui.py）

### 3.1 session_state 约定

在设计图导入函数所在作用域，增加一个用于存放本次结果的键，例如：

- `design_import_results`：`list[dict]`，每项字段建议：
  - `name`: str，原始文件名；
  - `status`: str，`"success" | "skipped" | "failed"`；
  - `message`: str，用户可见说明；
  - `imported_at`: str，可选，最近一次成功导入时间（用于 skipped 提示）。

### 3.2 写入导入结果

在当前导入循环中（伪代码）：

```python
results = []

for uploaded_file in files_to_process:
    file_name = getattr(uploaded_file, "name", "设计图")
    raw_bytes = uploaded_file.read()
    # ... hash, mime_type, PDF 分页等逻辑 ...

    try:
        full_description = ...  # 调用 _parse_design_image_with_gemini 得到文本
    except Exception as ex:
        results.append({
            "name": file_name,
            "status": "failed",
            "message": f"解析失败：{ex}",
        })
        continue

    # 入库（沿用现有 add_entry_with_dedup 调用）
    rowid, status = add_entry_with_dedup(
        DESIGN_MOCKUP_SOURCE_TYPE,
        full_description,
        source_id=file_hash[:16],
        title=f"设计图：{file_name}",
        summary=full_description[:500],
    )

    if status == "skipped":
        # 可选：查询最近一次导入时间
        latest_dt = _find_latest_design_import_time(file_hash_prefix=file_hash[:16])
        msg = "内容未变更，已跳过"
        if latest_dt:
            msg += f"（已于 {latest_dt} 导入）"
        results.append({
            "name": file_name,
            "status": "skipped",
            "message": msg,
        })
    else:
        # 调用 Librarian 摘要（沿用现有逻辑）
        with st.spinner(_get_text(T, "memory_tab.agent_summary_pending") or "生成摘要中…"):
            _generate_entry_summary(rowid, full_description, defaults.get("gemini_key", ""))
        results.append({
            "name": file_name,
            "status": "success",
            "message": "已解析并写入项目记忆",
        })

st.session_state["design_import_results"] = results
```

`_find_latest_design_import_time` 的实现可以通过 `memory_store.search` 或新加一个小查询函数（见 4.3）。

### 3.3 在 UI 中展示导入结果

在导入逻辑之后，追加渲染：

```python
results = st.session_state.get("design_import_results") or []
if results:
    st.markdown("**本次导入结果**")
    for r in results:
        prefix = "✅" if r["status"] == "success" else ("ℹ️" if r["status"] == "skipped" else "❌")
        st.caption(f"{prefix} {r['name']} — {r['message']}")
```

可根据文案需求将 caption 替换为 `st.markdown` 或 `st.text`，但避免影响整体布局（遵守 UI 规范）。

### 4.2 UI 渲染（app_ui.py）

在「项目记忆」Tab 中，建议在“导入历史时间轴”附近新增区块，并支持整体展开/收起：

```python
entries = ...  # 通过上文接口查询到的 design_mockup 记录

with st.expander("设计图历史", expanded=False):
    if not entries:
        st.caption("当前项目尚未导入任何设计图。")
    else:
        for e in entries:
            created = e.get("created_at", "")
            title = (e.get("title") or "").strip() or "设计图"
            # 从 title 或 content 中提取原始文件名（推荐在导入时就把文件名写入 title）
            show_title = title

            status = (e.get("agent_summary_status") or "pending").lower()
            if status == "success":
                tag = "有摘要✓"
            elif status == "failed":
                tag = "摘要失败✗"
            else:
                tag = "摘要待生成"

            label = f"[{created}] {show_title} · [{tag}]"
            with st.expander(label, expanded=False):
                # 摘要
                st.caption("摘要")
                if status == "success":
                    st.markdown(e.get("agent_summary", "") or "_（暂无）_")
                elif status == "failed":
                    st.caption("摘要生成失败")
                    if st.button("重试摘要", key=f"retry_design_summary_{e.get('id')}"):
                        ok, err = _generate_entry_summary(
                            e["id"],
                            e.get("content") or "",
                            defaults.get("gemini_key", ""),
                        )
                        if ok:
                            st.rerun()
                        else:
                            st.error(f"摘要生成失败：{err}")
                else:
                    st.caption("摘要待生成")

                st.divider()
                st.caption("设计图结构化描述（前 2000 字）")
                content = (e.get("content") or "").strip()
                st.markdown(content[:2000] + ("…" if len(content) > 2000 else ""))
```

> - `key` 值必须包含唯一的 `id`，避免按钮冲突；  
> - 避免在此区块中加入过多复杂布局，遵守现有 `st.container` 与列布局规范。

### 4.3 （可选）查询最近一次导入时间

用于在“已跳过”提示中展示“已于 XX 时间导入”。

简单方案（不扩展存储接口）：

```python
def _find_latest_design_import_time(file_hash_prefix: str, project_id: str | None = None) -> str | None:
    # 通过 list_recent 查找 design_mockup 记录，并根据 source_id 前缀匹配
    all_recent = list_recent(limit=100, project_id=project_id)
    ts = [
        e.get("created_at")
        for e in all_recent
        if e.get("source_type") == DESIGN_MOCKUP_SOURCE_TYPE
        and str(e.get("source_id", "")).startswith(file_hash_prefix[:8])
    ]
    if not ts:
        return None
    # 按时间排序，返回最新一条
    return sorted(ts)[-1]
```

若后续需要更精确的匹配，可考虑在存储层增加针对 content_hash 的反查接口。

## 五、多项目支持（如 Fambase / RM11）

- 所有设计图查询接口必须带 `project_id` 或通过 `current_project` 推导：
  - 导入时：`add_entry_with_dedup` / `add_entry` 已经支持 `project_id`，调用时传入当前项目；
  - 历史列表时：`list_recent` / `list_for_browse` 调用时带上 `project_id=_get_current_project()`。
- 切换项目后：
  - 导入结果列表（本次上传）可以清空；
  - 历史列表重新基于新项目查询并渲染。

## 七、Zip 解包与模型选择的实现细节

### 7.1 Zip 中多图解析优化（全量逐个解析）

在「导入设计图」区块中，增加对 `.zip` 文件的检测与解包逻辑：

```python
def _iter_design_images_from_upload(uploaded_file) -> list[tuple[str, bytes]]:
    \"\"\"将上传文件统一转换为 (文件名, 字节流) 列表。
    支持：单张 PNG/JPG/PDF 或包含上述文件的 zip 包。
    \"\"\"
    name = getattr(uploaded_file, \"name\", \"\")
    ext = (name or \"\").lower().rsplit(\".\", 1)[-1] if \".\" in (name or \"\") else \"\"
    raw = uploaded_file.read()

    if ext == \"zip\":
        import zipfile
        from io import BytesIO

        result: list[tuple[str, bytes]] = []
        with zipfile.ZipFile(BytesIO(raw)) as zf:
            for info in zf.infolist():
                if info.is_dir():
                    continue
                inner_name = info.filename
                inner_ext = inner_name.lower().rsplit(\".\", 1)[-1] if \".\" in inner_name else \"\"
                if inner_ext not in (\"png\", \"jpg\", \"jpeg\", \"pdf\"):
                    continue
                with zf.open(info) as f:
                    data = f.read()
                result.append((inner_name, data))
        return result

    # 非 zip：视为单个文件
    return [(name or \"设计图\", raw)]
```

导入流程中将原先对 `uploaded_file.read()` 的处理改为调用 `_iter_design_images_from_upload`，再按返回列表逐张解析，并结合已有的进度与结果反馈逻辑。

要点：

- 不再从 `defaults[\"gemini_model\"]` 或全局 `GEMINI_MODEL` 读取模型，用一个独立的免费模型配置环境变量控制；
