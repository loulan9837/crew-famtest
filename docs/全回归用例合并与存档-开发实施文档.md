## 三、行级精确去重 + 有序合并算法

### 3.1 规范化函数

```python
def _normalize_lines(text: str) -> list[str]:
    lines: list[str] = []
    for line in (text or "").splitlines():
        s = line.strip()
        if s:
            lines.append(s)
    return lines
```

### 3.2 合并函数

```python
from typing import List, Set

def merge_full_regression(existing: str, new: str) -> str:
    old_lines = _normalize_lines(existing)
    new_lines = _normalize_lines(new)

    merged_lines: List[str] = []
    seen: Set[str] = set()

    for line in old_lines:
        if line not in seen:
            merged_lines.append(line)
            seen.add(line)

    for line in new_lines:
        if line not in seen:
            merged_lines.append(line)
            seen.add(line)

    return "\n".join(merged_lines)
```

实现要点：

- 不排序，保持「旧 → 新」的自然顺序。
- 判重严格基于 `line` 字符串相等，不做大小写或空白归一。

## 四、导入流程改造（app_ui.py）

以下伪代码假设你已经在「项目记忆」Tab 中有全回归导入按钮逻辑。

### 4.1 解析新文件

```python
content_new, rows = parse_test_cases_file(test_cases_file)
if not content_new.strip():
    st.warning(_get_text(T, "memory_tab.file_empty") or "文件内容为空")
    return
```

### 4.2 写入存档记录

```python
from datetime import datetime
import hashlib

now_id = datetime.now().strftime("%Y%m%d_%H%M%S")
hash_prefix = hashlib.sha256(content_new.encode("utf-8")).hexdigest()[:8]
import_id = f"{now_id}_{hash_prefix}"

archive_source_id = f"full_regression:{import_id}"

add_entry_with_dedup(
    TEST_CASES_SOURCE_TYPE,
    content_new,
    source_id=archive_source_id,
    title=f"全回归测试用例 - {file_display_name}",
    summary=content_new[:500],
)
```

> 说明：  
> - 是否允许同一内容多次存档，由 `add_entry_with_dedup` 的 hash 去重逻辑决定；  
> - 若不希望重复存档，可接受 `status="skipped"` 即可。

### 4.3 读取当前聚合视图

```python
existing = get_entry_content(TEST_CASES_SOURCE_TYPE, "full_regression") or ""
```

### 4.4 合并并写回聚合视图

```python
merged_content = merge_full_regression(existing, content_new)

rowid, status = add_entry_with_dedup(
    TEST_CASES_SOURCE_TYPE,
    merged_content,
    source_id="full_regression",
    title="全回归测试用例（聚合）",
    summary=merged_content[:500],
)

if status == "skipped":
    st.info("导入内容与现有聚合结果一致，未产生新增用例。")
else:
    # 可选：标记 context cache / Agent 知识库为脏
    try:
        from context_cache_service import mark_context_cache_dirty
        mark_context_cache_dirty(f"test_cases_{status}")
    except ImportError:
        pass
    # 可选：生成/刷新 Librarian 摘要
    with st.spinner(_get_text(T, "memory_tab.agent_summary_pending") or "生成摘要中…"):
        _generate_entry_summary(rowid, merged_content, defaults.get("gemini_key", ""))
    st.success(f"已合并 {rows} 行全回归用例（含历史记录去重）。")
```

## 七、测试与回归要点

### 7.1 功能测试

- 场景 A：
  - 先导入 `A 模块全回归.xlsx`；
  - 再导入 `B 模块全回归.xlsx`；
  - 预期：
    - 存档中有两条 `full_regression:*` 记录；
    - 聚合视图包含 A 和 B 的所有行，重复行只出现一次。

- 场景 B：
  - 已有 A、B 后再导入 C；
  - 预期：
    - 聚合视图为 A∪B∪C 的行级并集；
    - 存档中有三条记录。

- 场景 C：
  - 导入一份与当前聚合视图完全相同的 Excel；
  - 预期：
    - 聚合视图不变；
    - UI 提示“未产生新增用例”或等价文案。

### 7.2 回归测试

- 文档问答与生成用例功能：
  - 验证 Agent 上下文中“全回归用例”部分确实是 A∪B∪C 的内容，而不是最后一次导入单独一份；
  - 其余项目记忆内容（需求文档、设计图、run_summary）不受影响。

- 多项目场景（如 Fambase / RM11）：
  - 各项目的存档记录与聚合视图均带正确的 `project_id`；
  - 不同项目之间的全回归用例不会串数据。
