# 全站UI与文案优化 · 落地风险分析

> **文档用途**：对照 `docs/全站UI与文案优化-PRD.md`，标出**易被实现成业务/逻辑变更**的条目，便于研发只做 **UI、交互与文案** 落地。  
> **关联文档**：`全站UI与文案优化-PRD.md`、`交互反馈优化-PRD.md`  
> **分析日期**：2026-04-17

---

## 一、分析前提

PRD 已声明：

- 不新增或删减功能模块；
- 不改变 Agent 编排、存储、同步、导出等**业务逻辑**；
- 实现载体主要为 `app_ui.py` 与 `config/ui_texts.yaml`。

本分析聚焦：**哪些条文在落地时若理解偏了，会动到「非纯展示」代码**（条件分支、状态聚合、与后端阶段不一致的呈现等）。

---

## 二、风险分级说明

| 级别 | 含义 |
|------|------|
| **高** | 易引入新条件、假进度或展示语义与真实执行不一致 |
| **中** | 多为 UI 默认值/折叠，但需显式约定，避免顺带改触发条件 |
| **低** | 以文案、组件替换、`yaml` 为主，与业务逻辑解耦 |

---

## 三、条文对照与风险

### 3.1 高风险

#### （1）生成用例 · 分阶段加载文案（PRD §7.2）

**原文要点**：分阶段文案优于单一「正在生成…」；不改变后端阶段，仅文案与进度呈现。

| 风险 | 若实现为「多段进度条/多句阶段」而**后端仍单步阻塞**，用户会误以为存在可观测阶段，**呈现与真实不一致**。 |
| 缓解 | **仅当现有代码已暴露阶段或回调**时，为各阶段配置独立文案；否则保持**单次**加载提示，只优化**单句**措辞。禁止为「好看」伪造不存在的阶段。 |

#### （2）项目记忆 · 导入结果合并为一条摘要（PRD §7.5）

**原文要点**：导入结果多状态合并为一条结果摘要，减少多处重复 `success/warning`。

| 风险 | 从多处即时提示改为「一条摘要」，往往需要**会话内聚合展示状态**（先收集再一次性 `st.success`/`warning`），属于**展示层逻辑**，易与「何时算导入结束」纠缠。 |
| 缓解 | 聚合**仅影响展示顺序与条数**，不改变导入 API 调用次数、返回值含义及持久化结果；若需 `session_state`，仅存 **UI 展示用** 缓冲，不写新业务字段。 |

#### （3）文档问答 · 无上下文时禁用输入（PRD §7.6）

**原文要点**：无文档上下文时，输入区置灰或禁用 + 单行引导。

| 风险 | 若当前未实现禁用，则属于**新增 UI 门禁**（何时可发送），需与「文档上下文」的**既有**判定一致，避免新写一套业务规则。 |
| 缓解 | 门禁条件**只读**现有 session/状态；不新增「何谓有上下文」的业务定义，仅把已有布尔条件反映到 `disabled`。 |

#### （4）提示 · 「本次会话不再提示」（PRD §5.2）

**原文要点**：C 级说明可走「本次会话不再提示」；实现走 `session_state`，不改变业务数据。

| 风险 | 会新增 **dismiss 标志** 与条件渲染，虽非业务数据，仍是**可维护状态**，需避免与关键 A 级提示混用。 |
| 缓解 | **仅限 C 级**说明性横幅；A/B 级（安全、保存结果、致命错误）**不得**用「不再提示」隐藏。 |

---

### 3.2 中风险

| 条文 | 说明 |
|------|------|
| **§7.2** 模型配置「默认折叠；未配置 Key 时自动展开」 | 根据 Key 是否存在设置折叠默认态，属 **UI 条件**，不动校验与调用顺序；实现时注明：**仅控制 expander 初始展开**。 |
| **§4 / §7.1** 侧栏云端记忆「默认折叠」 | 一般为 `expander`/容器默认收起；**不要**改变记忆同步按钮的实际可用性或触发逻辑。 |
| **§7.6** 对话历史「默认折叠」 | 布局与 `expanded=False`；不改变历史加载 API 或条数。 |

---

### 3.3 低风险（与「仅 UI/文案」一致）

- **§2.2 非目标**、**§9.2** 功能与数据结果与改版前一致。
- **§5.1** 提示分级、**§6** 文案原则、**§8** 空态/错误最低标准：以 `caption`、`expander`、弱化横幅、`ui_texts.yaml` 为主。
- **§9.1**「3 秒内可识别主操作」：体验目标，**不应**实现为定时器或强制跳转逻辑。

## 四、建议写入 PRD 的「落地边界」（可选补丁）

下列边界**已并入** [全站UI与文案优化-PRD.md](./全站UI与文案优化-PRD.md) **§2.4**（PRD **V1.1**），实现以 PRD 为准：

> **落地边界**：凡涉及合并提示、分阶段加载、禁用输入、会话内「不再提示」，仅允许调整 **Streamlit 展示层** 与 **`session_state` 中的 UI 专用标志**（如折叠默认、dismiss、展示用聚合缓冲）。不得新增或删减接口调用、不得变更存储 schema、不得改变 Agent 编排步骤或与改版前不一致的数据结果。分阶段文案仅绑定**已有**执行阶段；若无阶段信息，则保持单次加载文案。

---

## 五、验收时额外关注（防串味）

| 检查项 | 说明 |
|--------|------|
| 回归对照 | 同一路径下，改版前后**导出文件、同步结果、生成表结构**一致 |
| 加载呈现 | 无「假阶段」；有阶段则与代码中的阶段一一对应 |
| 禁用输入 | 禁用条件与「文档上下文」既有定义一致，无新规则 |
| 合并提示 | 仅改变**出现次数与位置**，不改变导入/同步**成功失败判定** |
