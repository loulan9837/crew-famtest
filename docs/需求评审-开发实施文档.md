## 二、UI（`app_ui.py`）

### 2.1 结构（仅此，勿加子页）

1. `st.subheader` / `st.caption`（文案 `_get_text`）  
2. `st.text_area`：**唯一输入**，`key="requirement_review_paste"`  
3. `st.button`「开始评审」：`key="requirement_review_run"`  
4. 有 `result_md` 时 `st.markdown`；无结果时可不展示大块占位，或一句空态 caption  

**不要**：文件上传、radio 选来源、多步向导、单独「清除结果」按钮（非必须；若加，二期再说）。

### 2.2 切换页面缓存（必做）

与《页面切换保留输入》一致：

- 渲染 `text_area` **前**调用 `_restore_widget_state("requirement_review_paste", "")`  
- `text_area` 增加 `on_change=_make_persist_callback("requirement_review_paste")`  

**评审结果**不挂在 widget 上，用模块级 session 存一份即可：

- `result_key = _get_module_state_key(MODULE_REQUIREMENT_REVIEW, "result_md")`  
- 评审成功后将 Markdown 字符串写入 `st.session_state[result_key]`；页面再次进入时若存在则 `st.markdown` 展示。

（无需再维护一套 `persist_ui_` 镜像给「纯展示结果」，除非希望与 widget 行为完全一致；**推荐仅用 `result_key` 存结果**。）

### 2.3 点击「开始评审」（单一路径，避免歧义）

**推荐实现**：在 **`with st.spinner(...):`** 内 **同步调用** `generate_requirement_review_questions(...)`，**不要**用「先 `running=True` + `st.rerun()` 再在下一轮调模型」——Streamlit 下徒增复杂度。

流程：

1. `text = st.session_state.get("requirement_review_paste", "")` 或从 widget 取值，`strip()` 为空 → `st.warning`，`return`  
2. 无 `gemini_key` → `st.error`，`return`  
3. `spinner` 内：入参前对正文 `desensitize_for_llm`，再调服务层  
4. 成功：`st.session_state[result_key] = 返回的 md`；失败：`st.error`，**不**清空粘贴与旧结果（若产品希望失败仍保留上次成功结果，保持 `result_key` 旧值即可）  

按钮在调用期间可用 `disabled=st.session_state.get("_req_review_busy", False)` 等极简标志；若仅用 spinner 同步阻塞，**甚至可以不设 busy 标志**（一次点击只触发一次脚本重跑）。

## 三、服务层（`risk_report_service.py`）

新增 **`generate_requirement_review_questions(document_content, gemini_model="", gemini_key="") -> str`**：

- 空文档 / 无 Key → `raise ValueError`（由 UI 转成 `warning`/`error`）  
- Prompt 固定：

```text
你是一位资深测试工程师。请审阅以下需求，指出其中逻辑模糊、不完整或存在风险的地方，直接列出几条核心疑问点，不要废话。

【需求文档】
{document}
```

- `document`：脱敏后截断（如 30000 字）  
- `ChatGoogleGenerativeAI` + `invoke`；异常处理：**一层 try/except** 即可，是否重试 429 与现有 `generate_risk_assessment_report` **对齐即可**，不必单独写复杂策略  

**不要**与 `generate_risk_assessment_report` 共用入口函数。
