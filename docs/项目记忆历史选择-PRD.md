# 项目记忆历史选择下拉 · 产品需求文档

> **文档用途**：为「项目记忆」与相关模块补齐“历史记录可选”的能力，避免每次刷新页面后用户看不到之前导入/选择的项目记忆记录，并提供一个下拉方式快速选择历史项。
>
> **关联文档**：`项目记忆-RAG与上下文管理-PRD.md`、`项目记忆-重新规划实施方案.md`

---

## 一、背景与问题

### 1.1 当前行为

- 项目记忆的**实体数据**（需求文档、全回归用例、设计图等）已存入 `memory_store`（SQLite/JSON），本质上是**持久化的**；
- 但在 Web 端：
  - 部分“最近选择的项目记忆”仅存在于 `st.session_state` 中；
  - 刷新页面或切 Tab 后，之前选择的记录/视图状态会丢失；
  - 用户主观感受为：“原来的项目记忆记录都消失了”。

### 1.2 用户痛点

- 每次刷新后：
  - 无法一眼知道「项目里到底已经有哪些项目记忆记录」；
  - 无法直接从一个统一的下拉里选中某条历史记录作为当前上下文；
  - 容易误以为历史导入数据都不见了。

---

## 二、目标与范围

### 2.1 目标

| 目标 | 说明 |
|------|------|
| 历史可见 | 在页面刷新后，项目记忆历史记录仍然可通过 UI 清晰可见（依托 `memory_store` 持久化） |
| 下拉选择 | 提供一个“项目记忆历史下拉框”，用户可从中选择某条历史记录作为当前的项目记忆上下文 |
| 状态友好 | 最近一次选择的历史项，在同一会话内切 Tab 或轻度刷新后，仍能通过下拉默认选中该项（若记录仍存在） |
| 多模块复用 | 同一套历史下拉能力可被「文档问答」「需求风险分析」等模块复用，避免多处重复实现 |

### 2.2 范围

- 本期聚焦：
  - 「项目记忆」Tab；
  - 「需求风险分析」模块中，选择“项目记忆”作为文档来源时的历史选择；
  - 可选：「文档问答」模块中，选择“项目记忆模式”时的历史选择。
- 不在本期范围：
  - 历史记录的删除/归档策略变更（沿用现有逻辑）；
  - 高级筛选与标签管理（如按模块/版本筛选）。

---

## 三、功能需求

### 3.1 项目记忆 Tab：历史下拉 + 时间轴

在原有「项目记忆」Tab 中，基于现有“导入历史时间轴”能力，补充一个简洁的下拉选择器。

**展示与交互：**

- 在“导入历史时间轴”上方，新增一行：
  - Label：`最近项目记忆`；
  - 控件：`selectbox` / 下拉框；
  - 选项来源：调用 `memory_store.list_recent(limit=N, project_id=current_project)`，按时间倒序取最近 N 条（默认 20 条）。
- 下拉项展示文案格式（示例）：
  - `[{时间}] {标题或文件名}（{source_type}）`
  - 如：`[2026-03-03 14:30] v6.5_paid_media_解锁列表（design_mockup）`

**行为：**

- 用户从下拉中选中某条记录后：
  - 下方的时间轴列表自动滚动/定位并高亮对应条目（如可行）；
  - 或在旁边展示该条记录的内容预览（标题 + 摘要 + 前若干字符的 content）。
- 最近一次选择的记录 ID 存入 `st.session_state`（如 `memory_last_selected_id`），在同一 Streamlit 会话内再次进入项目记忆 Tab 时：
  - 若该 ID 仍存在于 list_recent 返回的集合中，则默认将下拉选中这一项；
  - 若不存在（已删除或不在最近 N 条中），则回退到“未选择”状态。

### 3.2 需求风险分析模块：从项目记忆选择文档

在「需求风险分析」模块中，已有“从项目记忆中选择近期文档”的逻辑。本需求要求：

- 使用与项目记忆 Tab 相同的 `list_recent(limit=N, project_id=...)` 接口；
- 通过下拉选择的方式展示近期项目记忆记录：
  - 同样包含时间、标题/文件名、类型信息；
- 最近一次选择的条目在同一会话内保持默认选中（若记录仍存在）。

### 3.3 文档问答模块（可选，本期可做基础支持）

若文档问答模块存在“项目记忆模式”的选项，则：

- 提供一个与上述一致的历史下拉，用于选择具体某条项目记忆记录作为问答上下文；
- 默认策略同上：最近一次选择的 ID 在同一会话内尽量保持。

## 四、数据与状态约定

### 4.1 Data Source

- 所有历史下拉都统一调用 `memory_store` 提供的接口：
  - `list_recent(limit=N, project_id=current_project)`；
  - 未来如有更丰富筛选，可封装 service 层（不在本期）。

### 4.2 Session State

- 统一使用命名规则，例如：

| Key | 说明 |
|-----|------|
| `memory_last_selected_id` | 项目记忆 Tab 的最近一次下拉选择的记录 ID |
| `risk_report_last_memory_id` | 需求风险分析模块的最近一次项目记忆选择 ID |
| `chat_last_memory_id` | 文档问答模块的最近一次项目记忆选择 ID |

> 约束：这些 session_state 仅在当前 Streamlit 会话内有效，关闭浏览器或重新部署后重新初始化；实际历史数据依旧存放在 `memory_store` 中。

---

## 五、异常与约束

- 若 `memory_store` 不可用（MEMORY_AVAILABLE=False）：
  - 历史下拉不展示，仅展示相应的“项目记忆不可用”降级提示；
  - 现有粘贴模式继续可用。
- 若当前项目下找不到任何项目记忆记录：
  - 历史下拉展示为禁用状态，文案提示“当前项目暂无项目记忆记录，请先在『项目记忆』页导入”；
  - 不报错、不崩溃。

## 六、验收标准

| 编号 | 验收项 |
|------|--------|
| AC1 | 在「项目记忆」Tab 中，刷新页面后仍能看到一个“最近项目记忆”下拉，列出当前项目最近导入的项目记忆记录（至少时间 + 标题/文件名）。 |
| AC2 | 用户从下拉中选择某条记录后，下方时间轴或预览区立即同步显示该记录的详细内容；再次进入该 Tab 时，若数据仍存在，该记录在下拉中保持默认选中。 |
| AC3 | 在「需求风险分析」模块选择“项目记忆”作为文档来源时，可以通过下拉选择近期项目记忆记录，并在同一会话内保持最近一次选择。 |
| AC4 | 若 `memory_store` 不可用或当前项目没有任何记录，历史下拉自动禁用并显示友好提示，不影响粘贴模式的正常使用。 |
