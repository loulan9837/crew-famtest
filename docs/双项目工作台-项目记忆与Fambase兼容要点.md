# 双项目工作台 · 项目记忆与 Fambase 兼容要点

> **文档用途**：在《双项目工作台-PRD.md》基础上，单独明确「两个平台的项目记忆（全回归用例 + 设计图）」能力对称性，以及「现有 Fambase 项目记忆不受影响」的约束与验收。实现时需与本要点对齐。
>
> **关联文档**：`docs/双项目工作台-PRD.md`

---

## 一、双项目项目记忆：全回归用例与设计图

### 1.1 能力对称

- Fambase 与 RM11 在项目记忆 Tab 中拥有**完全对称**的导入能力：
  - 需求文档（粘贴/上传）
  - **全回归用例**（上传/粘贴）
  - **设计图**（上传 PNG/JPG/PDF，Gemini Vision 解析）
  - 从本次运行追加
- 写入时均带当前 `project_id`；导入历史、搜索、删除、摘要重试仅展示与操作**当前项目**数据，互不展示对方数据。

### 1.2 产品表述建议（可同步到主 PRD 或 UI 文案）

- 在功能描述中可明确写：
  - 「导入入口：需求文档、全回归用例、设计图、从本次运行追加——写入时均带当前 project_id；Fambase 与 RM11 在 UI 上拥有完全对称的导入能力（同样支持上传全回归用例与设计图），互不展示对方数据。」

---

## 二、Fambase 存量项目记忆兼容（关键约束）

### 2.1 原则

- 现有 Fambase 项目记忆在启用双项目工作台后必须**原样保留**：
  - `memory_entries` 中的所有历史记录
  - `project_memory.md`（或等价 Fambase 摘要文件）
  - Agent 知识库（Fambase 部分）
- **不清空、不重建、不改写内容**。

### 2.2 存量数据迁移策略

| 数据 | 策略 |
|------|------|
| memory_entries | 在 schema 升级时，对现有记录统一补写 `project_id = 'FAMBASE'`；新增 RM11 记录时写入 `project_id = 'RM11'` |
| project_memory 摘要 | 若采用分文件方案（如 `project_memory_fambase.md` / `project_memory_rm11.md`），将现有 `project_memory.md` 直接视为 Fambase 文件；RM11 新建独立文件 |
| Agent 知识库 | 若采用分文件方案，现有 Fambase 知识库文件对应 Fambase；RM11 新建独立文件；构建时仅读取当前项目 memory |

### 2.3 范围约束

- 本期改造视为在现有 Fambase 项目上**新增一个 RM11 项目空间**；
- Fambase 现有项目记忆默认归属 `project_id = FAMBASE`，不做重建。

## 三、补充验收标准（与主 PRD 配合使用）

实现双项目时，除主 PRD 中 AC1～AC8 外，建议增加以下验收项：

| 编号 | 验收项 |
|------|--------|
| AC9 | 在 Fambase / RM11 两个项目下，项目记忆 Tab 中均支持上传/粘贴**全回归用例**与**设计图**，导入历史仅展示当前项目数据，切换项目后互不串数据 |
| AC10 | 启用双项目后，与改造前对比，**Fambase 项目记忆**（导入历史、摘要、知识库）记录数量与内容完全一致；**RM11 项目记忆**初始为空，后续导入仅在 RM11 视图中可见，不影响 Fambase 视图 |
