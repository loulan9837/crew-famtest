# 全站UI视觉风格与换肤方案

> **文档用途**：在不动业务逻辑的前提下，给出**整体视觉风格**的定义、**设计令牌**与**落地方式**，作为对 [全站UI与文案优化-PRD.md](./全站UI与文案优化-PRD.md) 的**视觉层补充**。  
> **实现主入口**：`app_ui.py` 内 `_render_main_app` 注入的全局 `<style>`（约 `L1153–L1209`）；后续可抽离为独立样式模块，但首版允许仍集中维护。  
> **边界**：与PRD **§2.4落地边界**一致，换肤仅改展示层CSS与布局类用法，不改接口与数据流。

---

## 一、现状摘要

当前已有一套**轻量设计系统**：

- **色板**：主色青绿系（`#0d9488`）、背景浅灰（`#f8fafc`）、成功/错/警告独立色。
- **版心**：主内容区 `max-width: 960px` 居中。
- **圆角**：卡片与按钮统一 `12px`/`10px` 量级。
- **组件覆盖**：`stExpander`、`stButton` primary、`stTextInput`/`stSelectbox` 圆角、`stSuccess`/`stError`/`stWarning`/`stInfo` 与 `[data-testid="stAlert"]` 圆角。
- **侧栏**：原生结构，primary按钮已染主色。

缺口不在「有没有CSS」，而在**风格未形成完整规范**：侧栏与主区层级、信息密度、辅助色与中性色阶梯、分割线语义、上传区与空态的**统一容器语言**尚未写进文档，换肤时容易只改主色而整体仍散。

---

## 二、风格定位（推荐方向）

以下为一组**可一次性落地**的整体取向，便于研发与评审对齐；若产品后续要品牌化，只需替换**令牌表**而非推翻交互。

| 维度 | 推荐取向 | 说明 |
|------|----------|------|
| 气质 | 专业工具型SaaS | 冷静、清晰、略偏B端；避免营销页大渐变铺满 |
| 对比度 | WCAG方向可读 | 正文与背景对比足够；状态色不仅依赖色相 |
| 主色 | 保留青绿或微调饱和度 | 与现有用户心智连续；大改色相需同步更新侧栏与按钮预期 |
| 中性色 | Slate系层级 | 标题、副标题、说明、禁用、边框四条灰阶固定 |
| 密度 | 中等 | 主流程留白充足；列表与历史区可略紧 |
| 图标与emoji | 收敛使用 | 导航与按钮少而准；避免标题与正文堆emoji |

**可对标的公共模式**（非照搬界面）：现代文档型/协作工具常见的「浅底+白卡片+单色主按钮+细边框分割」，与当前Streamlit能力匹配。

### 2.1 与交互边界

换肤**不改变**侧栏导航与页面路由（如`current_page`）、当前页判定、以及各步按钮`disabled`/可用条件等**既有实现**；仅允许调整CSS、间距与外层`container`装饰，**不得**借机改写条件分支或触发逻辑。为规避`session_state`与控件身份错乱，**不新增、不重排、不重命名**带`key`的`st.*`控件；若仅增加无key的包装容器，仍须在回归中确认主路径行为与改版前一致。

## 三、Streamlit约束（换肤必须接受的物理限制）

| 能力 | 说明 |
|------|------|
| 布局 | 流式自上而下；大范围「悬浮固定顶栏」成本高且易破坏规则 |
| 主题 | 可通过 `st.set_page_config` 与自定义CSS覆盖部分原生外观；**全站暗色**需额外覆盖变量与对比，工作量大，建议**单独立项** |
| 组件 | `st.chat_message`、`st.file_uploader` 等内部结构随版本变化，CSS选择器需标注**脆弱性**，升级Streamlit后要回归 |
| 一致性 | 自定义HTML与`st.*`混用时，视觉需靠**同一套令牌**拉齐 |

结论：本方案以 **CSS变量 + 有限选择器** 为主，**不**承诺像素级与任意网页一致。

## 四、设计令牌 Design Tokens（建议稿）

以下为**推荐默认值**；落地时写入 `:root { ... }`，与现有变量**对齐或扩展**（可保留原键名，避免大面积替换）。

### 4.1 色彩

| 令牌 | 用途 | 建议值（可迭代） |
|------|------|------------------|
| `--color-primary` | 主按钮、关键链接、步骤标签 | 维持 `#0d9488` 或微调为略深一点的青绿以增强正文对比 |
| `--color-primary-dark` | hover/active | 维持或随主色联动 |
| `--color-primary-light` | 弱强调、hover背景 | 维持 |
| `--color-bg-main` | 主区背景 | `#f8fafc` |
| `--color-bg-elevated` | 侧栏或抬升区（若需与主区区分） | `#ffffff` 或 `#f1f5f9` |
| `--color-bg-card` | 卡片、Expander内容区 | `#ffffff` |
| `--color-border-subtle` | 分割线、边框 | `#e2e8f0` |
| `--color-text-primary` | 页面主标题 | `#0f172a` |
| `--color-text-secondary` | 小节标题、强调弱一级 | `#334155` |
| `--color-text-muted` | 说明、caption | `#64748b` |
| `--color-success` / `--color-error` / `--color-warning` | 状态 | 与现有一致或微调饱和度 |
| `--color-info-bg` | info类提示底（若单独区分） | 浅蓝灰，与`stInfo`背景协调 |

### 4.2 字阶与字重

| 用途 | 建议 |
|------|------|
| 页面标题 `h1` | 约 `1.5rem–1.65rem`，`font-weight:600`，`letter-spacing`略紧 |
| 区块标题 `h2` | 约 `1.05rem–1.15rem`，`600` |
| 小节 `h3` | 约 `0.95rem`，`500` |
| 正文 | 约 `0.95rem`，行高 `1.55–1.65` |
| caption | 约 `0.8–0.85rem`，`color: var(--color-text-muted)` |

说明：当前`h1`等为`!important`覆盖，换肤时**保留**对原生主题的覆盖策略，避免半屏原生半屏自定义。

### 4.3 圆角、阴影、间距

| 令牌 | 建议 |
|------|------|
| `--radius-card` | `10–14px` 二选一全站统一 |
| `--radius-button` | 略小于或等于卡片圆角 |
| `--shadow-card` | 轻阴影 `0 1px 2px` 或 `0 1px 3px rgba(0,0,0,0.06)`，避免重投影 |
| 区块纵向间距 | 主区块之间 `1.25–1.5rem`；列表项内 `0.5–0.75rem` |

### 4.4 侧栏专项

| 项 | 建议 |
|------|------|
| 导航按钮 | 继续用`type="primary"`表示当前页；secondary为未选中 |
| 分组标题 | 使用统一`h3`或caption样式，避免多种`markdown`字号 |
| 分割线 | `st.divider()` 颜色与 `--color-border-subtle` 对齐（可在CSS中调`hr`） |

侧栏**外观**见上表；**导航行为、当前页逻辑与控件key约束**以 **§2.1** 为准。

## 五、组件级视觉规范

### 5.1 主内容区

- **版心**：维持居中；若未来「表格过宽」投诉多，可单独对「结果页」放宽`max-width`（仅布局，不改数据）。
- **首屏**：主输入与主按钮在同一视觉「卡片带」内（通过`st.container`+统一`class`或内联样式类名），与历史区用**间距+分割线**区分。

### 5.2 Expander

- 继续作为**次级配置**容器（模型、历史对话等）；边框与阴影与`.card-style`一致，避免一种有阴影一种没有。

### 5.3 提示 Alert

- 成功/警告/错误/信息四类：**圆角+内边距**已部分覆盖；换肤时统一四类**左边框或图标侧色条**（可选，需测试Streamlit结构）。
- 与PRD一致：**减少横幅数量**优先于「把横幅做得更花」。

### 5.4 表单控件

- `text_input`、`selectbox`、`text_area`：**边框圆角**与卡片圆角同族。
- `file_uploader`：原生外观强依赖主题；至少保证**与上下文字体、间距**一致。

### 5.5 进度与加载

- `st.progress`、`st.spinner`：文案短句化；视觉不新增假阶段条（见PRD **§7.2**）。

## 六、换肤落地步骤（建议三阶段）

### 阶段A：令牌固化（低风险）

1. 将现有颜色与圆角**全部收口到`:root`**，补齐**文本色、边框色**变量。
2. 用变量替换样式块内硬编码十六进制色（除需刻意固定的对比色）。
3. 自测：各模块跑一遍，确认无选择器失效。

### 阶段B：层级与容器统一（中风险，仍属UI）

1. 定义**页面区块**的两种容器：`page-section`（无阴影仅留白）与`page-card`（白底浅阴影），在关键页面试点。
2. 侧栏分组标题与主区`title`字阶对齐文档第四节。

### 阶段C：精细化与回归（持续）

1. 针对`st.chat_message`、下载按钮等做**最小必要**覆盖。
2. Streamlit升级后做一次**视觉回归清单**（见第八节）。

## 八、验收清单（视觉专项）

| 项 | 标准 |
|----|------|
| 令牌一致性 | 主色、灰阶、圆角、阴影在主页与设置页无明显跳变 |
| 侧栏 | 当前页按钮与未选中状态对比清晰，不依赖emoji区分功能 |
| 可读性 | 正文与背景对比可长时间阅读；状态色与语义一致 |
| 脆弱CSS | 对`data-testid`的覆盖有注释，升级Streamlit后可查 |
| 业务无关 | 导出文件、生成结果、存储与换肤前一致 |
| 主路径可交互 | 换肤后主要路径上按钮可点击、输入框可聚焦与输入、文件上传可选；无`pointer-events`、伪元素或装饰层误挡控件等**CSS回归** |
| session_state安全 | 未对带`key`控件做新增/重排/重命名；若有仅容器级调整，经主路径冒烟与关键页切换验证 |
