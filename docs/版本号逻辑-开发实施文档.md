# 版本号逻辑 · 开发实施文档（YYYY-MM-DD-NNN）

> **依赖**：`docs/版本号逻辑-PRD.md`、`config/version.yaml`、`app_ui.py` 侧栏版本展示逻辑。
>
> **目标**：在现有版本展示实现基础上，约束版本号格式为 `YYYY-MM-DD-NNN`，并规范「会话中约定版本号 → 写入配置 → 部署 → 线上校验」的工程流程。

---

## 一、涉及文件与现状

| 文件 | 作用 |
|------|------|
| `config/version.yaml` | 保存当前应用版本号与可选构建时间 |
| `app_ui.py` | 在侧栏与设置页展示版本号，已存在 `_load_version()` 与展示逻辑 |
| `config/ui_texts.yaml` | `app.version_label` 文案配置 |

现有实现（摘要）：

- `version.yaml` 示例：

```yaml
version: "1.0.0"
build_time: ""
```

- `app_ui.py` 中：
  - 有 `_load_version()` 函数读取上述文件；
  - 在侧栏底部通过 `st.caption` 展示「版本: {version} (build_time)」。

本次改动是在**不改变读取与展示机制**的前提下，规范 version 字段的格式与使用流程。

---

## 二、版本号格式与写入规则

### 2.1 格式校验（约定）

- 版本号必须符合正则表达式：

```text
^\d{4}-\d{2}-\d{2}-\d{3}$
```

例如：

- 合法：`2026-03-03-001`、`2026-12-31-015`
- 非法：`2026-3-3-1`、`1.0.0`、`2026-03-03`、`2026-03-03-0001`

> 工程层面可以暂不强制正则校验（由人工约束），后续可在 `_load_version()` 中增加简单校验并在不符合时打印警告。

### 2.2 写入流程

1. 部署前，在会话中确定本次版本号，例如：`2026-03-03-001`。
2. 编辑 `config/version.yaml`：

```yaml
version: "2026-03-03-001"
build_time: "2026-03-03 14:25"
```

3. 保存文件并纳入本次提交。

> 建议：在提交信息中附带版本号，例如：`feat: 更新项目记忆逻辑 (version: 2026-03-03-001)`，便于 Git 历史追踪。

## 三、侧栏展示逻辑（现有实现的补充说明）

### 3.1 `_load_version()` 函数

确保该函数：

- 从 `config/version.yaml` 读取 `version` 与 `build_time`；
- 文件不存在或解析失败时，返回空 dict，不抛异常。

示意：

```python
def _load_version() -> dict:
    try:
        import yaml
        if not os.path.isfile(VERSION_PATH):
            return {}
        with open(VERSION_PATH, "r", encoding="utf-8") as f:
            data = yaml.safe_load(f) or {}
        return {
            "version": (data.get("version") or "").strip(),
            "build_time": (data.get("build_time") or "").strip(),
        }
    except Exception:
        return {}
```

### 3.2 展示逻辑

侧栏展示逻辑沿用现有实现，仅补充一点：不再假设版本号为 `x.y.z`，直接把字符串原样展示即可：

```python
ver_info = _load_version()
ver_str = ver_info.get("version", "")
if ver_str:
    ver_label = _get_text(T, "app.version_label") or "版本"
    ver_display = f"{ver_label}: {ver_str}"
    build_time = ver_info.get("build_time")
    if build_time:
        ver_display += f" ({build_time})"
    st.caption(ver_display)
```

## 四、部署与验证流程（工程规范）

### 4.1 部署前

1. 在当前沟通/需求会话中明确本次部署版本号：
   - 例如：「这次部署是 `2026-03-03-001`」。
2. 更新 `config/version.yaml`：
   - 将 `version` 改为 `2026-03-03-001`；
   - 可选填写 `build_time`。
3. 提交变更，并在提交信息中附带版本号：
   - 例如：`chore: bump version to 2026-03-03-001`。

### 4.2 部署中

- CI/CD 或手工部署脚本不需要特别逻辑，只要从主分支拉取最新代码即可。
- 可选增强（后续）：
  - 在 CI 日志中打印当前 `config/version.yaml` 中的 `version`：

    ```bash
    echo "Deploying version: $(grep '^version' config/version.yaml | awk '{print $2}')"
    ```

### 4.3 部署后验证

1. 打开线上应用，刷新页面；
2. 在侧栏或「设置」页查看版本号：
   - 应与会话中约定的 `YYYY-MM-DD-NNN` 完全一致；
3. 若不一致或仍为旧值：
   - 说明部署未生效或部署目标环境与预期不符；
   - 需检查 CI/CD 流水线或部署命令是否针对正确分支/环境。

## 五、扩展点（可选）

### 5.1 简单正则校验与告警

在 `_load_version()` 成功读取版本号后，可增加简单的格式校验：

```python
import re

_VERSION_PATTERN = re.compile(r"^\d{4}-\d{2}-\d{2}-\d{3}$")

def _load_version() -> dict:
    # 读取逻辑同上
    info = {...}
    ver = info.get("version", "")
    if ver and not _VERSION_PATTERN.match(ver):
        # 仅打印日志或在前端 caption 中追加小提示，避免抛异常
        print(f"[WARN] version.yaml 中的版本号格式不符合 YYYY-MM-DD-NNN：{ver}")
    return info
```

### 5.2 设置页中的版本详情

在设置页中增加一小块“版本信息”：

- 展示：
  - 当前版本号；
  - 构建时间；
  - Git 提交哈希（如后续接入 CI 自动写入）。
