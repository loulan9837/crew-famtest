# 页面切换保留用户输入 · PRD

> **文档用途**：定义工作台在侧栏切换模块（页面）时，用户已填写、已上传、已选择的内容应如何保留，避免重复劳动与误操作。  
> **受众**：产品、测试、研发验收。  
> **创建日期**：2026-03-30

---

## 一、问题陈述

当前（或未实现本需求时），用户在某一模块中：

- 粘贴了需求或测试用例文本；
- 上传了文件；
- 选择了来源、模型、筛选条件等；

若切换到其他模块（例如从「生成用例」到「设置」）再切回，**上述输入可能丢失**。用户期望行为与多数 Web 表单一致：**在同一会话内，除非用户主动清空或关闭浏览器/Tab 导致会话结束，否则应保留其输入**。

本需求适用范围为 **全站各工作台模块**（以 `workbench_apps` / 侧栏可切换的模块为准）。

---

## 二、目标与成功标准

### 2.1 目标

1. **会话内持久**：在同一浏览器标签页、未主动清除会话的前提下，侧栏切换模块后返回，用户可见内容与切换前一致（在下列「范围内」）。
2. **不替代业务持久化**：本需求解决的是 **UI 状态在导航中的保留**，不替代「保存到文件 / 数据库」等显式持久化；但若用户仅切换页面而未点保存，仍应看到其未提交的编辑。
3. **与产品铁律兼容**：不改变「生成用例仅支持上传与粘贴、禁止外部文档入口」等既有产品约束。

### 2.2 验收标准（Acceptance Criteria）

**本期 P0 验收（发版必须满足）：**

| 编号 | 场景 | 期望结果 |
|------|------|----------|
| P0-AC-1 | 生成用例：粘贴文本或上传文件后，切到「设置」再切回 | 粘贴内容与上传文件（或等价展示/可继续用于生成）仍可用 |
| P0-AC-2 | 设置：**非敏感字段**（如模型选择、开关类配置）在未保存时，切到其他模块再切回 | 表单中仍显示用户刚才的输入；Key 等敏感字段不在本期范围内 |
| P0-AC-3 | 用户主动「清空」「结束对话」「重置」等操作 | 对应区域按产品设计清空，不保留旧输入 |

**后续 P1 建议覆盖（本期不作为发版阻断条件）：**

| 编号 | 场景 | 期望结果 |
|------|------|----------|
| P1-AC-1 | 项目记忆：搜索词、导入区粘贴、全回归上传/粘贴等，切换模块后再进入 | 相应输入保留 |
| P1-AC-2 | 需求风险分析、文档问答、用例补充、用例对话等含多控件模块 | 主要输入控件在切换后保持一致（见下表范围） |

## 三、范围（按模块）

### 3.1 必须覆盖（P0）

- **生成用例**：需求来源、粘贴模式下的文本、上传文件列表或缓存、相关模型选择等。
- **设置（本期仅限非敏感字段）**：模型选择、开关类配置等；API Key 等敏感字段**不**纳入本期「页面切换保留输入」范围。

### 3.2 应覆盖（P1）

- **项目记忆**：搜索、需求导入粘贴、标题、全回归用例上传/粘贴、高级摘要编辑区等。
- **用例补充**：补充说明/指令类输入。
- **历史记录**：筛选条件（若有）。
- **需求风险分析**：文档来源、粘贴内容。
- **文档问答**：文档来源、粘贴内容。
- **编辑 Agent**：YAML 路径与可编辑表单（若与 widget 绑定）。

### 3.3 用例对话（特殊说明）

- **粘贴类需求/用例**：切换模块后应保留。
- **从历史记录选择**：若底层实现为「每次运行新建选项对象」，需单独约定是否用 **记录 ID** 或 **索引** 持久化，避免恢复失败；见开发实施文档。

### 3.4 非目标（本期可不做）

- 跨标签页、跨浏览器、跨设备的同步。
- 用户关闭浏览器后仍保留（除非已有独立「本地持久化」产品需求）。
- 对 `st.chat_input` 等无稳定 `key` 或版本差异大的组件：若技术限制无法可靠保留，应在界面说明或后续迭代处理。

## 四、与多项目工作台的关系

本项目已引入 `current_project` 与双项目工作台（如 `FAMBASE` 与 `RM11`），页面切换保留输入需与「项目切换」对齐：

- **作用域**：页面切换保留输入仅在同一 `current_project` 内生效。  
  - 例如：在 `FAMBASE` 下粘贴 PRD → 切到「设置」或其他模块 → 回到 `FAMBASE` 的「生成用例」，应能看到此前输入。  
  - 若切换为 `RM11`，则视为进入另一套独立工作台，其未保存输入独立管理。
- **项目切换的作用**：
  - 对「需求输入型模块」（如生成用例、项目记忆导入区、用例补充、需求风险分析、用例对话粘贴区），切换 `current_project` 仅切换到对应项目的草稿命名空间，不清空其他项目已有的草稿，也不会在新项目中复用旧项目的输入。
  - 对「全局通用型模块」（如设置页中的模型选择等非敏感字段），输入草稿可在项目间复用。
- **示例验收用例**：
  - 在 `FAMBASE` 下的「生成用例」中粘贴一段 PRD 文本 A；  
    → 切换到 `RM11` 的「生成用例」，此时不应自动带入 A；  
    → 再切回 `FAMBASE` 的「生成用例」，页面应恢复显示 A。

## 五、草稿优先级与生命周期

### 5.1 草稿 vs 已保存优先级

- 对存在「显式保存」动作的区域（如设置、项目记忆摘要），显示优先级为：  
  **未保存草稿（persist_ui_*） > 上次显式保存的持久化值**。
- 若当前显示内容为未保存草稿，需在对应区域以文案显式提示，例如：  
  - 「当前内容为未保存草稿，如需写入项目记忆请点击保存」  
  - 文案统一配置在 `config/ui_texts.yaml`，避免硬编码。
- **例外：设置页敏感字段（Key）**  
  - Key 字段本期不纳入「页面切换保留输入」范围，既不保留草稿，也不在 AC 中做要求。  
  - 如未来需要支持 Key 草稿，需单独起安全评审与专门 PRD。

### 5.2 生命周期与清理策略

- 会话粒度：默认以「当前浏览器 Tab + 当前运行会话」为粒度；不跨浏览器、不跨设备。
- 浏览器刷新后：默认可以尝试恢复 persist 草稿，但需通过显式「重置/清空」按钮一键清理，避免长期会话污染。
- 本期仅使用内存态的 `session_state` 存储 `persist_ui_*`，**不写入磁盘**。  
  - 若未来引入本地持久化（如 `localStorage` / 本地 yaml 文件）方案，需另起 PRD 与安全评审。

## 六、交互与文案

- 原则上 **不新增**「已为您自动保存草稿」等提示，除非用户研究认为需要；默认静默恢复。  
  对需要提示「未保存草稿」的区域，通过简短说明落在局部区域。
- 若某控件因技术原因无法保留，应在该模块内用简短说明（文案走 `config/ui_texts.yaml`），避免用户困惑。

---

## 七、风险与合规

- **敏感信息**：设置页中的 Key 等已在既有规范中处理；本需求不得将敏感信息写入日志或新明文文件。
- **多开标签**：以 `session_state` 隔离为既有约束；本需求不引入全局变量。

---

## 八、实施配套说明摘要（给开发/测试）

- **与双项目工作台的边界**：  
  页面切换保留输入仅在同一 `current_project` 内生效；切换项目时，仅切换当前使用的项目草稿命名空间，不清空其他项目已有草稿，全局通用设置可跨项目复用。
- **草稿优先级**：  
  对有显式「保存」动作的区域，未保存草稿优先展示，但需通过文案告诉用户当前是草稿，需要保存才会写入持久化存储。
- **敏感字段例外**：  
  设置页中的 Key 等敏感字段不参与本期 persist；测试在验收时明确排除这些字段。
- **非目标重申**：  
  `st.chat_input` 跨页草稿、编辑 Agent 复杂配置草稿均为**非本期目标**，不作为本次发版的验收范围；如需支持，需单独 PRD 与实施方案。
