## 优化建议一：文档职责拆分（灾备 vs 项目记忆业务）

### 背景问题

- `数据持久化与自动备份-方案.md` 与检查清单当前重心在 **Postgres+R2 冷备、manifest、恢复、裂脑、合规**，与用户侧诉求 **「设计图/全回归/Agent 用项目记忆如何永久存、何时写入、每次生成读什么」** 不在同一抽象层。
- 若不在文档上划界，易出现误解：**「有定时备份 = 业务上记忆已正确、Agent 已单次读完」**——二者不等价。

### 建议动作

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **收窄主方案声明** | 在 `数据持久化与自动备份-方案.md` 文首或「〇、适用范围」下增加一句：**本文仅规范 Postgres 与 R2 的冷备、恢复与合规，不定义项目记忆如何被 Agent 消费或何时重建知识库。** |
| 2 | **新增独立短文（推荐）** | 新建 `项目记忆持久化与Agent读取策略.md`（名称可调整），专门写：① 三类持久化对象（设计图对象、全回归原文、供 Agent 的浓缩记忆制品）；② 写入触发（如全回归导入成功后刷新记忆）；③ 读取契约（生成用例默认读哪一层、是否过渡期多读 `memory_entries`）；④ 设计图仅追加与「最新」的 **DB 字段 SoT**（如 `created_at`/单调 `id`）；⑤ 与 `current_project` / `project_id` 隔离。可与 `Agent知识库-PRD.md` 合并演进，但避免与灾备长文混为一篇。 |
| 3 | **检查清单增补** | 在 `数据持久化与自动备份-检查清单与审阅要点.md` 增加一节 **「项目记忆业务与灾备边界」**，勾选项示例：是否另有文档定义 Agent 读取单一制品；回归导入后记忆刷新是否定义；设计图 append-only 与「最新」字段是否定义；`current_project` 隔离是否在记忆链路中落实。 |

### 预期效果

- 运维/安全评审主看 **灾备方案**；产品/研发验收 **记忆策略** 有独立入口，互不替代。

## 优化建议二：产品铁律与可验收口径（可直接并入 PRD）

### 背景问题

- 需求口述包含：**永久存储**、**一次消化进项目记忆**、**生成用例尽量只读项目记忆**、**设计图只增不改由 Agent 分新旧**、**回归间歇手动导入后更新记忆**。
- 其中「Agent 自己判断哪张设计图最新」若无 **数据库排序 SoT**，易产生不可复现的推理差异。

### 建议写入 PRD 的验收口径（草案）

以下可整体或拆条并入 `Agent知识库-PRD.md`、双项目相关 PRD 或新建的「项目记忆持久化与 Agent 读取策略」文档：

1. **永久存储**  
   设计图文件、全回归导入内容、以及面向 Agent 的项目记忆制品（如按项目的 `agent_knowledge` 或等价表/文件）均落在 **Postgres+R2（或方案既定持久层）**，不以 Streamlit `session_state` 或单次进程为 SoT。

2. **摄入与触发**  
   全回归为**间歇手动导入**；每次成功导入且校验通过后，**自动触发一次**「写入/刷新 Agent 可用项目记忆」流程（**已拍板**）。显式「刷新知识库」可作为补刷。设计图入库为**仅追加**；是否与每次入库联动增量摘要，单独列为可选或非目标。

3. **读取契约**  
   生成测试用例时，四 Agent **默认仅读取**当前 `project_id` 下的「项目记忆制品」；原始设计图与全回归在**重建记忆制品**时由服务读取，**不要求**每次生成请求全量重喂原文。若一期无法做到，须写明**过渡期**仍合并 `memory_entries` / 近期条目的范围与淘汰计划。

4. **设计图「最新」**  
   「最新」以 **入库时间或单调 ID** 等 DB 字段为准，列表或注入上下文时**先排序再交给模型**；**禁止**将「谁最新」完全交给模型在无结构数据上自由推断。

5. **去重与仅追加**  
   与 `设计图导入-PRD.md` 对齐：若采用内容哈希去重，则「同图再传」不新增版本；若产品改为「每次上传均新版本」，须**显式改写**去重策略，避免与「仅追加」语义冲突。

6. **双项目**  
   灾备可为整库备份；应用层须保证记忆制品与导入数据按 **`project_id`/`current_project`** 隔离，避免 Fambase 与 RM11 上下文串用。
