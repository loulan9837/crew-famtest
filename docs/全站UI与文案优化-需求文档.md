## 二、目标与成功标准

### 2.1 业务目标（体验）

- 用户能在**约 3 秒内**识别当前页主操作（主观体验目标，**不得**用定时器或强制跳转实现）。
- 提示信息**可分级扫读**：阻断类显著、反馈类克制、说明类不抢占主任务区。
- 文案**短句化、动作化**，全站术语一致（含中英边界不加空格等产品规范）。

### 2.2 约束目标（必须同时满足）

- 改版前后，**同一路径**下的**功能行为与数据结果**与改版前一致（见 §六）。
- 「生成用例」仍**仅**支持上传与粘贴，不引入外链等违规入口。

---

## 三、范围

### 3.1 包含

- `app_ui.py` 中的组件层级、折叠默认态、`st.expander`/`caption`/`placeholder` 等**展示层**调整。
- `config/ui_texts.yaml`（及必要时的键结构）中的**用户可见文案**收敛与增补。
- 为落实 PRD 所需的 **`session_state` 展示层专用标志**（如 C 级「不再提示」、折叠记忆、导入结果**展示用**聚合缓冲等），**不写业务持久化字段**。

### 3.2 不包含（禁止）

- 新增或删除功能模块；改变云端同步、存储 schema、导出列、Agent 任务图。
- 新增或删减 API 调用次数；改变导入/同步/生成的**成功失败判定**。
- 伪造多阶段进度：无后端阶段时，加载区**仅允许单条**文案优化。
- 将体验指标实现为**定时器、强制跳转、阻塞逻辑**。

详细禁区见 PRD **§2.4** 与开发实施方案 **§二**。

## 四、功能需求（按主题）

### FR-1 全站提示分级

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-1.1 | A/B/C 三级用途与表现与 PRD §5.1 一致 | 高风险信息不被「清爽化」到不可见 |
| FR-1.2 | C 级说明优先 `caption`/`help`/折叠，避免长 `st.info` 霸屏 | 主任务区视觉焦点提升 |
| FR-1.3 | B 级成功反馈靠近操作区，同会话同类成功不重复轰炸 | 与 §7 各页落地一致 |
| FR-1.4 | 可选：C 级支持「本次会话不再提示」 | **仅** C 级；实现为展示层 `session_state` 标志 |

### FR-2 文案与术语

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-2.1 | 关键界面文案优先来自 `ui_texts.yaml` | 硬编码中文持续减少 |
| FR-2.2 | 术语统一（如 API Key、Excel、Agent、PRD） | 抽检多页一致 |
| FR-2.3 | 错误提示含用户可执行的一步恢复动作 | 技术细节可折叠或仅日志 |

### FR-3 侧栏（§7.1）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-3.1 | 弱化品牌口号高度；版本信息沉底、弱视觉 | 不改变导航与路由逻辑 |
| FR-3.2 | 云端记忆快捷区默认折叠（`expanded=False`） | **不**改变同步/回填/按钮可用性的业务逻辑 |

### FR-4 生成用例（§7.2）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-4.1 | 首屏顺序：来源→主输入→主按钮；模型配置默认折叠 | 未配置 Key 时 expander 可自动展开，**仅**控制初始展开态 |
| FR-4.2 | 顶部配置状态改为单行或轻量条 | 不新增校验规则 |
| FR-4.3 | 无结果时用空态卡片（标题+一句引导+主按钮）替代长 `info` | 不改变生成触发条件 |
| FR-4.4 | 加载：有真实阶段则文案与阶段一一对应；否则单次加载文案 | **禁止**假阶段 |

### FR-5 历史记录（§7.3）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-5.1 | 空态含「创建第一份用例」类引导 | 文案可配置 |
| FR-5.2 | 删除确认短而明确，强调不可恢复与已下载文件不受影响 | 不改变删除实际行为 |

### FR-6 需求评审 / 需求风险分析（§7.4）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-6.1 | 三段式信息结构清晰；价值一句话 | 不改服务层与模块 ID |

### FR-7 项目记忆（§7.5）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-7.1 | 分块折叠：搜索与最近、导入、全回归、设计图、云端同步等 | 仅布局与默认展开 |
| FR-7.2 | 长风险说明：摘要+详情展开，避免警告墙 | 不改变部署检测逻辑 |
| FR-7.3 | 导入结果多提示合并为一条摘要 | 聚合**仅**影响展示；API 与持久化结果与改版前一致 |

### FR-8 文档问答 / 用例对话（§7.6）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-8.1 | 无文档上下文时输入区禁用或置灰+单行引导 | `disabled` **仅映射既有**上下文判定 |
| FR-8.2 | 推荐问题/快捷指令命名风格统一 | 文案与组件 |
| FR-8.3 | 对话历史默认折叠 | 不改变历史 API 与条数 |

### FR-9 设置（§7.7）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-9.1 | Key、模型、额度等单卡片聚合；保存反馈局部化 | 保存逻辑不变 |
| FR-9.2 | 「返回」为次级导航 | 路由行为不变 |

### FR-10 空态 / 加载 / 错误（§8）

| ID | 描述 | 验收要点 |
|----|------|----------|
| FR-10.1 | 空态含标题+一句说明+一个主行动点 | 禁止仅「暂无数据」 |
| FR-10.2 | 加载含明确进行中；防重复提交遵守《交互反馈优化》 | 不新增并发协议 |
| FR-10.3 | 错误含原因+一步恢复；技术细节可折叠 | — |

## 五、非功能需求

| 项 | 要求 |
|----|------|
| 技术栈 | Streamlit 原生能力为主，避免重度自定义 CSS/绝对定位 |
| 可维护性 | 文案键集中管理；展示层标志位命名可读、可检索 |
| 无障碍与认知 | 高风险操作保留确认与后果说明（与 PRD §2.3 一致） |
| 安全 | 不引入新日志泄露敏感信息；规范与 `.cursor/rules/project-standards.mdc` 一致 |

## 六、验收标准（与 PRD §9 对齐）

### 6.1 体验

- 核心路径主操作可快速识别；说明性横幅明显减少；高风险仍有清晰确认。

### 6.2 范围与回归

- **功能行为与数据结果**与改版前一致（对照测试）。
- 文案以 `ui_texts.yaml` 为主。

### 6.3 防串味（必测）

| 检查项 | 预期 |
|--------|------|
| 同路径对照 | 导出、同步、生成表结构等与改版前一致 |
| 加载呈现 | 无假阶段 |
| 禁用输入 | 条件与既有「文档上下文」定义一致 |
| 合并提示 | 仅展示层变化，成功/失败判定不变 |
