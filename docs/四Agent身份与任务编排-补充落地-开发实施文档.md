## 二、待审稿与落点映射

### 2.1 身份（`agents[].backstory`）

在 `config/agents.yaml` 中，将待审稿 **§二～§五** 各节 **```text``` 块内全文**（含标题行 `【…（补充）】` 与条目），**追加**到对应 `id` 的 `backstory:` 多行字符串 **末尾**，与原有 `backstory` 之间建议空一行，避免粘连。

| `agents.yaml` 中的 `id` | 待审稿章节 |
|-------------------------|------------|
| `doubt_agent` | §二 |
| `organize_agent` | §三 |
| `case_agent` | §四 |
| `review_agent` | §五 |

**禁止**：删除或改写既有 `backstory` 中与 Fambase、审查维度、排版红线、优先级、表结构相关的原文；仅 **追加**。

### 2.2 优化方向（§〇）是否单独写入 YAML

待审稿 **§〇** 为 PM 共识，**不要求**在 YAML 中重复一整表；推荐二选一：

- **推荐**：不单独增加字段，§〇 精神已通过 §二～§五 各节「对齐」融入补充段；评审时以待审稿 §〇 为验收口径。  
- **可选**：在四个 `backstory` 追加段 **之前** 增加一行总领句（从 §〇 表格压缩为 1～2 句），内容须与待审稿一致，**不得**超出待审稿表述。

### 2.3 任务编排（`tasks[]`）— 仅当 §六 Go 时

待审稿 **§六** 为可选；若 PM 决定 **Go**，在 **不增删占位符、不改 task id/agent_id/context**** 前提下，向 `description` **末尾**追加短句（措辞以 PM 定稿为准，下表为待审稿原意）：

| `task` id | 追加意图（待审稿原句摘要） |
|-----------|----------------------------|
| `task3` | 强调逐条展开 2 号大纲，**不得省略**测试点 ID 对应关系 |
| `task4` | 强调对**步骤粒度**与**断言可判定性**按补充规则**抽检全表** |

若 **No-Go**：仅合并 §二～§五 `backstory`，**不动** `tasks[].description`。

**禁止**：在 `description` 中引入新占位符；改变 `{prd_content}` / `{project_context}` / `{taskN_output}` 出现位置与顺序的语义（避免解析或 Crew 注入歧义）。

## 三、规格说明同步

合并 YAML 后，更新 **`docs/四Agent提示词与任务编排-规格说明.md`**：

| 规格文档章节 | 同步内容 |
|--------------|----------|
| **§2.1～§2.4**（各 Agent 系统指令摘要） | 与 `agents.yaml` 各 `backstory` **追加后的完整语义**一致；可将「补充段」单独列为子小节，便于 diff |

## 四、与「全回归 / 项目上下文」的关系（不改代码前提）

待审稿 §〇 要求对齐 **全回归用例** 与 **整个项目** 视角。当前流水线中 **`{project_context}`** 由既有逻辑注入（项目记忆摘要、全回归摘要等，以 `crew_test` 与 UI 配置为准）。

| 要求 | 实施说明 |
|------|----------|
| **本补充落地** | 不修改 `crew_test` 内 `project_context` 的拼装逻辑；通过 **强化 Agent 指令** 要求模型 **充分利用** 已注入的 `{project_context}`，与 PRD 对照做模块与回归面推演 |
| **若发现 context 过短或缺失** | 属 **数据/管道** 问题，不在本文范围；需单独 PRD 或「项目记忆注入」专项，**不可**仅靠 YAML 臆造未注入的全文 |

## 五、实施步骤（建议顺序）

1. **备份**：复制当前 `config/agents.yaml`（或 git 分支/commit）。  
2. **合并 backstory**：按 §2.1 对四个 `id` 依次追加 §二～§五 `text` 块。  
3. **§六 决策**：若 Go，按 §2.3 追加 `task3` / `task4` 的 `description` 短句。  
4. **自检 YAML**：缩进、`|` 多行字符串闭合、无 Tab 混用；可选 `yamllint` / IDE 校验。  
5. **同步规格**：按 §三 更新 `四Agent提示词与任务编排-规格说明.md`。  
6. **待审稿元数据**：在 `四Agent身份定义-补充建议-待审.md` 修订记录中标注「已批准并合入 agents.yaml 的日期与版本」（由合并人填写）。
