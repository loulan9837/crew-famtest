# 项目记忆持久化与 Agent 读取策略

> **文档用途**：定义「设计图 / 全回归 / 面向 Agent 的记忆制品」如何持久化、何时写入与刷新、生成用例时读哪一层；与 **灾备冷备**（`数据持久化与自动备份-方案.md`）**职责分离**。  
> **来源**：采纳 `docs/数据持久化与项目记忆-文档优化建议.md` 建议一之独立短文 + 建议二之验收口径。  
> **更新时间**：2026-04-02（§2.2：全回归导入成功后 **自动** 刷新记忆/知识库已拍板）

---

## 〇、与灾备文档的边界

| 文档 | 回答的问题 |
|------|------------|
| `数据持久化与自动备份-方案.md` | Postgres+R2 **如何备份、恢复、manifest、裂脑调和** |
| **本文** | 业务数据 **SoT 在哪**、**何时写入记忆制品**、**四 Agent 默认读什么**、**设计图「最新」如何用 DB 排序** |

**误区纠正**：存在定时冷备 **不等于** 线上「记忆已正确注入」或「Agent 已按产品预期单次读完」；二者分开验收。

## 一、三类持久化对象（概念层）

| 类型 | 说明 | 典型载体（随架构演进可调） |
|------|------|---------------------------|
| **A. 设计图对象** | 原始或解析前文件字节 | R2 对象 + DB 元数据（`object_key`、hash 等） |
| **B. 全回归原文** | 导入的全量/合并用例原文 | DB 条目 + 必要时 R2 |
| **C. Agent 用记忆制品** | 供四 Agent 默认消费的浓缩上下文（如 `agent_knowledge` 或等价表/文件） | Postgres 行或项目级文件，**按 `project_id` 隔离** |

重建 **C** 时，服务可读取 **A/B** 与 `memory_entries` 等源数据；**不要求**每次生成请求全量重喂 **A/B** 原文（见第三节）。

---

## 二、写入与触发（验收口径）

### 2.1 永久存储（SoT）

设计图文件、全回归导入内容、以及面向 Agent 的项目记忆制品（如按项目的 `agent_knowledge` 或等价表/文件）均落在 **Postgres+R2（或方案既定持久层）**；**不以** Streamlit `session_state` 或单次进程内存为 SoT。

### 2.2 摄入与触发

- **全回归**：产品定位为 **间歇手动导入**；每次 **成功导入且校验通过** 后，须 **自动触发一次**「写入/刷新 Agent 可用项目记忆」（含知识库制品重建或等价流程），**无需**用户再点「刷新知识库」。显式「刷新知识库」按钮仍可保留为 **补刷/重试** 入口，但不作为全回归导入后的必经步骤。  
- **设计图**：入库语义为 **仅追加**（append-only）；是否与每次入库联动增量摘要，列为 **可选** 或 **非目标**，单独声明。  
- **与 `设计图导入-PRD.md` 去重对齐**：若采用 **内容哈希去重**，则「同图再传」**不新增版本**；若产品改为「每次上传均新版本」，须 **显式改写** 去重策略，避免与「仅追加」语义冲突。

### 2.3 设计图「最新」（DB SoT）

「最新」以 **`created_at` / 单调 `id` 等 DB 字段** 为准；列表或注入上下文时 **先排序再交给模型**。  
**禁止** 在无结构数据上完全依赖模型推断「哪张设计图最新」。

---

## 三、读取契约（四 Agent）

- 生成测试用例时，四 Agent **默认仅读取** 当前 `project_id` 下的 **「项目记忆制品」（C）**。  
- **A/B** 在 **重建 C** 时由服务读取；**不要求** 每次生成请求全量重喂原文。  
- **过渡期**（若一期无法做到仅读 C）：须明文写出仍合并 `memory_entries` / 近期条目的 **范围、条数上限与淘汰计划**，避免长期双轨无文档。

---

## 四、双项目隔离

- 记忆制品、导入数据与读取范围均须按 **`project_id` / `current_project`** 隔离，避免 Fambase 与 RM11 **串上下文**。  
- **灾备**可为整库备份；**应用层**仍须保证上述隔离（与 `双项目工作台-项目记忆与Fambase兼容要点.md` 一致）。

---

## 五、验收检查（摘要）

1. SoT 不在 `session_state`。  
2. 全回归导入成功后，知识库/记忆制品 **自动刷新** 已实现且可验收（显式按钮仅作补刷可选）。  
3. 设计图仅追加；「最新」由 DB 排序；模型不单独裁决「最新」。  
4. 生成用例默认读 C；过渡期有文档化范围与退场计划。  
5. `project_id` 隔离在写入与读取链路均已落实。
