# 双项目工作台（Fambase / RM11）· 产品需求文档

> **文档用途**：在同一套 Streamlit 平台内支持 Fambase 与 RM11 两个项目的一键切换；Agent 定义与 Task 编排共用，项目记忆（需求文档/设计图/全回归用例）严格按项目隔离。
>
> **关联文档**：`项目流程总览.md`、`Agent知识库-PRD.md`、`项目记忆-重新规划实施方案.md`
>
> **创建日期**：2026-03-05

---

## 一、背景与目标

### 1.1 背景

- 当前平台为单项目设计，项目记忆、生成用例历史、文档问答语料均全局共用，无法区分「Fambase」与「RM11」两套独立业务。
- 测试与产品需要在同一工作台中交替维护两个项目的需求与用例，且两个项目的需求文档、设计图、全回归用例互不共用。
- Agent 提示词与四 Agent 流水线是通用能力，不应为每个项目复制一套工程。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 项目一键切换 | 侧边工作台顶部提供 Fambase / RM11 切换入口，切换后全站上下文与数据展示绑定当前项目 |
| 共用 Agent 与 Task | Agent 定义、Task 编排、模型与密钥配置全局共用，不按项目复制 |
| 项目记忆隔离 | 需求文档、设计图、全回归用例、导入历史、项目记忆摘要、Agent 知识库按项目维度隔离存储与展示 |
| 状态可追溯 | 所有依赖项目的状态统一通过 `st.session_state` 与 `project_id` 绑定，禁止裸全局变量 |

---

## 二、范围与非目标

### 2.1 范围

- 侧边栏新增「项目切换器」UI 与交互逻辑。
- `st.session_state` 中引入 `current_project`（取值 `FAMBASE` | `RM11`）及项目命名空间（如 `fambase.*` / `rm11.*`）下的状态。
- 项目记忆相关存储与 API 支持 `project_id` 维度：memory_entries、project_memory 摘要、Agent 知识库按项目切分或按 project_id 过滤。
- 生成用例、文档问答、需求风险分析、项目记忆四个模块的读/写/展示逻辑全部绑定当前 `current_project`。
- 设置模块保持全局；可选支持项目级配置（如模块映射文件、用例 ID 前缀）的扩展点。

### 2.2 非目标

- 不增加第三个及以上项目（本期仅 Fambase + RM11，扩展多项目为后续迭代）。
- 不改变四 Agent 流水线的调用方式与入参契约；仅在拼装 `project_context` 时按 project_id 过滤数据源。
- 不实现跨项目数据迁移或合并；项目间完全隔离。

## 三、核心概念与信息架构

### 3.1 概念定义

| 概念 | 定义 |
|------|------|
| 当前项目 (current_project) | 用户当前选中的项目，取值为 `FAMBASE` 或 `RM11`，决定所有「项目记忆」与「生成用例历史」的读写范围 |
| 项目记忆（按项目） | 某项目下的需求文档、全回归用例、设计图描述、运行摘要等 memory_entries 子集，以及该项目对应的 project_memory 摘要与 Agent 知识库 |
| 全局共用 | Agent 配置（Prompt/Task）、Gemini 密钥与模型、存储后端策略（SQLite/JSON）、应用版本号等与 project_id 无关的配置与逻辑 |

### 3.2 信息架构

```
Streamlit 平台
├── 全局壳（共用）
│   ├── 侧边导航结构
│   ├── Agent 配置页（Prompt / Task 编排）
│   ├── 设置页（API Key / 模型 / 存储 / 版本）
│   └── 项目切换器（选择 FAMBASE | RM11）
│
├── 项目空间 Fambase（隔离）
│   ├── 项目记忆（需求/设计图/全回归/摘要/知识库）
│   ├── 生成用例（输入/历史/导出）
│   ├── 文档问答（当前项目记忆模式下的语料）
│   └── 需求风险分析（当前项目上下文）
│
└── 项目空间 RM11（隔离）
    ├── 同上
    └── 与 Fambase 无交叉
```

## 四、功能详细定义

### 4.1 项目切换器（侧边栏顶部）

| 项 | 说明 |
|----|------|
| 位置 | 侧边栏最上方，在所有模块导航项之前 |
| 形态 | 横向分段选择：`[● Fambase] [○ RM11]`，可带简短描述（如 Fambase·社交直播 / RM11·风控规则引擎） |
| 默认值 | 首次进入或未持久化时，默认 `FAMBASE` |
| 交互 | 点击另一项目即切换；若当前存在「未保存的上传或表单」（由各模块自行上报），先弹出确认：「切换项目将清空当前未保存内容，是否继续？」确认后执行切换并清空相关临时状态 |

### 4.2 生成用例模块（按项目）

| 能力 | 说明 |
|------|------|
| 当前项目展示 | 页面顶部或标题旁展示「当前项目：Fambase」或「当前项目：RM11」 |
| 输入 | 上传/粘贴的 PRD、可选全回归 Excel，仅与当前 project_id 关联；临时缓存存入 `st.session_state` 时带 project 命名空间 |
| 运行 | 触发四 Agent 流水线时，`project_context` 仅从当前项目的项目记忆（memory_entries + project_memory + agent_knowledge）拼装，禁止读取另一项目数据 |
| 历史 | 生成用例历史列表仅展示当前项目的运行记录；切换项目后列表立即切换为该项目的记录 |

### 4.3 项目记忆模块（按项目）

| 能力 | 说明 |
|------|------|
| 摘要与知识库 | 项目记忆摘要文件与 Agent 知识库按项目区分（如 `project_memory_fambase.md` / `project_memory_rm11.md`，或表/字段带 project_id）；当前 Tab 只展示与编辑当前项目的摘要 |
| 导入入口 | 需求文档、全回归用例、设计图、从本次运行追加——写入时均带当前 project_id，入库接口增加 project_id 参数或等价存储结构；Fambase 与 RM11 在 UI 上拥有完全对称的导入能力，互不展示对方数据 |
| 导入历史 | 时间轴仅展示当前项目的条目；删除、搜索、摘要重试等操作仅作用于当前项目条目，互不影响另一项目 |
| 知识库刷新 | 可为每个项目单独展示「最后更新时间」与「刷新知识库」按钮；刷新时仅基于当前项目的 memory 与摘要构建该项目的知识库 |

### 4.4 文档问答模块（按项目）

| 能力 | 说明 |
|------|------|
| 模式 | 保留「单文档模式」与「项目记忆模式」；选择项目记忆模式时，检索与上下文仅来自当前 project_id 的项目记忆 |
| 提示 | 回答中可标明数据来源为「当前项目记忆（Fambase/RM11）」 |

### 4.5 需求风险分析模块（按项目）

| 能力 | 说明 |
|------|------|
| 文档来源 | 支持上传/粘贴单份 PRD，或从当前项目记忆中选择已导入的 PRD 条目 |
| 分析上下文 | 风险与历史对比仅基于当前项目的记忆与历史，不跨项目 |

### 4.6 Agent 配置与设置（全局）

| 模块 | 说明 |
|------|------|
| Agent 配置 | Prompt 模板、Task 编排、重试/温度等全局共用；若未来需项目级覆盖，可预留「为 RM11 单独覆盖」等扩展，本期可不实现 |
| 设置 | API Key、默认模型、存储后端、workspace 路径、版本号等均为全局，与 current_project 无关 |

## 五、UI 设计规范

### 5.1 侧边栏结构（自上而下）

```
┌─────────────────────────────┐
│  [● Fambase]  [○ RM11]      │  ← 项目切换器
│  当前项目：Fambase           │  ← 只读标签（可选）
├─────────────────────────────┤
│  生成用例                    │
│  项目记忆                    │
│  文档问答                    │
│  需求风险分析                │
│  Agent 配置                  │
│  设置                        │
└─────────────────────────────┘
```

### 5.2 各页与项目的关系

| 页面 | 是否随项目切换 | 说明 |
|------|----------------|------|
| 生成用例 | 是 | 切换后展示当前项目的输入区与历史列表，临时输入可清空 |
| 项目记忆 | 是 | 切换后展示当前项目的摘要、导入入口、历史时间轴、知识库区块 |
| 文档问答 | 是 | 项目记忆模式下的语料与当前项目一致；单文档模式可不变 |
| 需求风险分析 | 是 | 文档来源与风险上下文绑定当前项目 |
| Agent 配置 | 否 | 全局共用，不随项目切换 |
| 设置 | 否 | 全局共用 |

### 5.3 空态与首次使用

| 场景 | 说明 |
|------|------|
| 某项目首次进入项目记忆 | 展示引导：「该项目尚未导入任何需求/设计/全回归，建议先：1. 导入核心 PRD；2. 导入全回归用例；3. 导入关键设计图。」 |
| 某项目无记忆时生成用例 | 允许仅凭本次上传的 PRD 生成，并提示：「未检测到该项目的历史记忆，建议后续在项目记忆中补齐以提升用例质量。」 |
| 切换项目后 | 所有依赖项目的区块重渲染为该项目数据；无数据时显示对应空态，不展示另一项目内容 |

## 六、数据与状态设计

### 6.1 Session 状态约定

| Key 或命名空间 | 类型 | 说明 |
|----------------|------|------|
| `current_project` | str | `FAMBASE` \| `RM11`，侧边栏切换器唯一写入 |
| `fambase.*` / `rm11.*` | 命名空间 | 各模块可将项目相关临时状态放入对应命名空间（如 `fambase.uploaded_prd_text`），切换时清理旧项目命名空间 |
| 其他已有 key | 兼容 | 若现有 key 与项目强相关，迁移为带 project 前缀或按 project 存子键，避免多项目串数据 |

### 6.2 存储与持久化（建议）

| 数据 | 建议方案 |
|------|----------|
| memory_entries | 表或 JSON 中增加 `project_id` 字段；所有 list/add/delete/get 接口支持按 project_id 过滤 |
| project_memory 摘要 | 按项目分文件（如 `config/project_memory_fambase.md`、`project_memory_rm11.md`）或单文件内分块存储 |
| Agent 知识库 | 按项目分文件（如 `config/agent_knowledge_fambase.md`、`agent_knowledge_rm11.md`）或单文件+project_id 段；构建时仅读取当前项目 memory |
| 生成用例历史 | 现有 JSON 或 DB 中每条记录带 project_id；列表与导出仅查当前 project_id |
| 模块映射 | 可选：`fambase_modules.yaml` / `rm11_modules.yaml`，生成用例时按 current_project 加载对应文件 |

### 6.3 Fambase 存量项目记忆兼容（原则与迁移）

- 启用双项目工作台后，现有 Fambase 项目记忆必须**原样保留**，包括：
  - `memory_entries` 中的所有历史记录；
  - `project_memory.md`（或等价 Fambase 摘要文件）；
  - Agent 知识库中 Fambase 部分内容；
- 不清空、不重建、不改写上述内容，本期改造视为在现有 Fambase 项目上新增一个 RM11 项目空间。

| 数据 | 存量迁移策略 |
|------|--------------|
| memory_entries | 在 schema 升级时，对现有记录统一补写 `project_id = 'FAMBASE'`；新增 RM11 记录时写入 `project_id = 'RM11'` |
| project_memory 摘要 | 若采用分文件方案（如 `project_memory_fambase.md` / `project_memory_rm11.md`），将现有 `project_memory.md` 直接视为 Fambase 文件；RM11 新建独立文件 |
| Agent 知识库 | 若采用分文件方案，现有 Fambase 知识库文件对应 Fambase；RM11 新建独立文件；构建时仅读取当前项目 memory |

- Fambase 现有项目记忆默认归属 `project_id = 'FAMBASE'`，不做重建；RM11 项目记忆初始为空，只在 RM11 视图下通过导入入口逐步建立。

### 6.4 项目切换时的状态机（简化）

- 用户点击另一项目 → 若有未保存输入则弹窗确认 → 确认后：`current_project` 更新，清空当前页与项目相关的临时状态，不跳转页面但主内容区按新项目重渲染。
- 未保存输入：由各模块在切换前通过回调或统一接口上报（如「是否有未提交表单/未保存上传」），由项目切换器决定是否弹窗。

## 七、验收标准

### 7.1 功能验收

| 编号 | 验收项 |
|------|--------|
| AC1 | 侧边栏顶部展示 Fambase / RM11 切换器，点击可切换，当前选中有明显区分 |
| AC2 | 切换后，项目记忆 Tab 仅展示当前项目的导入历史与摘要；切换回另一项目后展示另一项目数据，无串数据 |
| AC3 | 生成用例页的历史记录仅展示当前项目；在新项目下生成用例后，历史中仅在该项目下可见 |
| AC4 | 生成用例时，四 Agent 使用的 project_context 仅包含当前项目的 memory 与知识库，不包含另一项目内容 |
| AC5 | 文档问答选择「项目记忆」模式时，检索与回答仅基于当前项目记忆 |
| AC6 | 需求风险分析从「当前项目记忆」选择文档时，仅列出当前项目的条目；分析结果不引用另一项目数据 |
| AC7 | Agent 配置页、设置页内容与项目无关，切换项目后内容不变 |
| AC8 | 若当前存在未保存内容且用户切换项目，弹出确认框；确认后切换并清空未保存内容；取消则保持原项目 |
| AC9 | 在 Fambase / RM11 两个项目下，项目记忆 Tab 中均支持上传/粘贴全回归用例与设计图，导入历史仅展示当前项目数据，切换项目后互不串数据 |
| AC10 | 启用双项目后，与改造前对比，Fambase 项目记忆（导入历史、摘要、知识库）记录数量与内容完全一致；RM11 项目记忆初始为空，后续导入仅在 RM11 视图中可见，不影响 Fambase 视图 |

### 7.2 非功能与约束

| 编号 | 验收项 |
|------|--------|
| NF1 | 所有依赖项目的读写均带 project_id 或 current_project，无裸全局变量存储项目相关数据 |
| NF2 | 项目记忆不可用时（MEMORY_AVAILABLE=False），两项目均降级，生成用例仍可用；行为与现有单项目降级一致 |
| NF3 | 双项目下，现有安全与防御规范（公式注入防护、目录遍历校验、密钥不入库等）保持不变 |

## 八、后续扩展预留

- 增加第三个项目：扩展 `current_project` 枚举与存储的 project_id 取值，项目切换器改为下拉或列表。
- 项目级 Agent 覆盖：在 Agent 配置页增加「按项目覆盖 Prompt」的可选配置，读取时优先取当前项目的覆盖配置。
- 项目级模块映射与用例前缀：设置或单独配置页中为每个项目配置 `modules.yaml` 与用例 ID 前缀（如 FAM- / RM-），生成用例时按当前项目读取。
