# 需求评审 · PRD

> **文档用途**：定义工作台「需求评审」模块的产品目标与验收标准。  
> **范围**：**仅支持粘贴文本 → 一键分析**；不追求复杂能力。  
> **创建日期**：2026-04-03（修订：范围与缓存说明）

---

## 〇、与「需求风险分析」的区分

仓库中 **`risk_report` 已用于「需求风险分析」**（表格报告、Excel 等）。「需求评审」使用 **独立模块 ID：`requirement_review`**，侧栏文案「需求评审」，**不得**复用 `risk_report`，避免路由冲突。

---

## 一、目标（保持简单）

| 项 | 说明 |
|----|------|
| 输入 | **仅粘贴文本**（`text_area`），不支持本模块内上传文件、外链、项目记忆拉取 |
| 操作 | 一个主按钮「开始评审」 |
| 输出 | 下方以 **Markdown** 展示模型返回的**核心疑问点**（列表形式即可） |
| 切换页面 | **同一浏览器会话内**，从其他工作台模块切回本模块时，**粘贴内容与上次评审结果仍保留**（实现上沿用全站 `session_state` / `persist_ui_*` 策略） |

### 明确不做（本期）

- 文件上传、多 Tab 子流程、历史记录列表、导出、数据库存盘。
- 「保留」指 **会话内** UI 状态不丢；**关闭浏览器或会话重置后不要求恢复**。

---

## 二、交互要点

| 场景 | 行为 |
|------|------|
| 空白粘贴就点「开始评审」 | `st.warning`：请先粘贴需求 |
| 评审中 | `st.spinner`，避免重复点击可用 `disabled` |
| 成功 | `st.markdown` 展示结果 |
| 失败 | `st.error`，粘贴内容不丢，可重试 |
| 未配置 Key | `st.error`，不崩溃 |

### AI 口径

资深测试工程师视角，列出逻辑模糊、不完整或有风险的**核心疑问点**，简练、少废话。系统 Prompt 与开发文档一致。

---

## 三、验收标准（AC）

| 编号 | 验收项 |
|------|--------|
| AC1 | 侧栏「需求评审」进入独立页，模块 ID 为 `requirement_review` |
| AC2 | 粘贴文本 →「开始评审」→ 下方出现 Markdown 疑问点 |
| AC3 | 无 Key 时有明确错误提示 |
| AC4 | 切换其他模块再切回，**同一会话内**粘贴内容与评审结果仍在 |
| AC5 | 可见文案来自 `ui_texts.yaml` |
